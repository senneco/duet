# Сервер и команда duet

Ядро (`core/`) работает в фоне и отдаёт себя клиентам по HTTP. Поведение — в `docs/specs/server.md`.

## Части

- `cmd/duet` — команда `duet`. Вся логика в `app/`.
- `app/` — фоновый запуск и команды: `duet web [review]`, `duet stop`, `duet serve` (само ядро, обычно его запускает `Ensure`), `duet install` и команды агента (`agent/README.md`).
- `server/` — HTTP поверх ядра: API, поток событий, веб-клиент (`server/web/`, встроен в программу).

## Фоновый запуск (`app/`)

- Любая команда начинается с `Config.Ensure()`: читает `~/.duet/server.json` (pid, порт, отпечаток сборки) и спрашивает ядро `/api/health`. Нет ответа — запускает `duet serve` отдельно от терминала (`setsid`, вывод в `~/.duet/server.log`) и ждёт его. Отвечает ядро другой сборки — просит его остановиться (`/api/shutdown`) и запускает своё. Команды агента на шаге 5f тоже начинаются с `Ensure`.
- Ядро на папку данных одно: `duet serve` держит `flock` на `~/.duet/server.lock`. Второй `serve` ждёт до 5 секунд (старое ядро может ещё останавливаться) и выходит.
- Отпечаток сборки — путь, размер и время файла программы (`app.Build`). Пересобрали или поставили новую — отпечаток другой.
- Порт 4848 на `127.0.0.1` и `::1`. Занят — берётся свободный, в `server.json` и в ссылке — он.
- Переменные окружения: `DUET_HOME` (папка данных), `DUET_PORT`, `DUET_BROWSER` (программа, которая открывает ссылку; по умолчанию `open` на macOS, `xdg-open` на Linux).
- `serve` раз в секунду вызывает `core.Watch` (следит за диском открытых ревью). Состояние ядро сохраняет после каждого действия, поэтому остановка ничего не теряет.

## API (`server/`)

Только эта машина: запрос с чужим `Host` (подмена адреса домена на эту машину) — 403; изменения принимаются только как JSON (чужой сайт не может прислать его без предварительного запроса, на который мы не отвечаем) и с `Origin` этой машины.

Чтение:

- `GET /api/reviews` — все ревью, новые сверху. Файлы без содержимого (только пути и состояния).
- `GET /api/reviews/{id}` — ревью, так же без содержимого. `response` — непросмотренный ответ: номер, время, файлы, которых он касается, сколько ответов и вопросов, сколько написано в окне ответа (`mine`) и сколько из этого не отправлено (`unsent`). У файла `absent` — текущей версии нет, файл есть только в ответе.
- `GET /api/reviews/{id}/file?path=` — файл целиком (`core.FileView`): база, текущая, ответ, диск, комментарии. Пока есть непросмотренный ответ, у комментариев файлов ответа есть `resp` — место в версии из ответа (для окна ответа).
- `GET /api/reviews/{id}/diff?path=&mode=base|response` — готовые куски отличий (`core.Chunk`): «база → текущая», «текущая → ответ».
- `GET /api/reviews/{id}/responses` — история ответов.
- `GET /api/health` — `{build}`.

Команды и хуки агентов — `POST /api/agent/...`, см. `agent/README.md`.

Действия — `POST /api/reviews/{id}/{action}` с JSON-телом: `sync`, `opened {path}`, `accept-file {path}`, `edit {path, content, from?, force?}` (`from` — текст, с которого начали править; поменялся — `changed-meanwhile`, `force` — сохранить всё равно), `editing {on}`, `revert {path}`, `accept-response`, `reject-response`, `interrupt`, `restore-anyway`, `send {inResponse}` (`inResponse` — из окна ответа: уходит только написанное в окне, агент продолжает поверх непринятого ответа), `comment {path, range?, text, images, inResponse, was?}` → `{id}` (`was` — комментарий к удалённому тексту: что было; `range` — точка, где это было), `comment-edit {id, text, images}`, `comment-delete {id}`, `reply {id, text, images}`, `dismiss {id}`. `POST /api/shutdown` — остановить ядро.

Картинки в комментариях — `POST /api/images {data: "data:image/png;base64,…"}` → `{path, url}`: файл в папке данных (`images/`, имя по содержимому), `path` уходит в `images` комментария — его открывает агент, `url` (`GET /api/images/{имя}`) — для клиента.

Ошибки — `{error, message, paths?}`: `error` — код, по нему клиент выбирает текст на своём языке (`unviewed-response`, `agent-working`, `disk-changed` с `paths`, `no-agent`, `stopping`, `nothing-to-send` и т. д., список в `codes`). 404 — нет ревью или файла, 409 — ядро запретило действие.

События — `GET /api/events` (Server-Sent Events):

- `hello {build}` — первым при каждом подключении. Отпечаток поменялся — клиент перезагружает страницу.
- `change {reviews}` — какие ревью поменялись; клиент перечитывает те, что показывает. Источник — `core.Subscribe`: ядро помечает ревью при каждом сохранении, при правке с диска и при смене пометок «изменён на диске».
- `sync {review, done, total}` — прогресс сверки с диском; `done == total` — сверка закончена.
- `reset` — клиент отстал, пусть перечитает всё.

Клиент при каждом подключении (и после перезапуска duet) заново открывает ревью: `sync`, потом читает его.

## Веб-клиент (`server/web/`)

Поведение — `docs/specs/` (шаг 6a: `docs/changes/06a-reading/proposal.md`, шаг 6b: `docs/changes/06b-comments/proposal.md`, шаг 6c: `docs/changes/06c-response/proposal.md`), вид — макет D `docs/changes/06a-reading/mockups/d-keyboard.html`, комментарии — `docs/changes/06b-comments/mockups/comments.html`, окно ответа — вариант E `docs/changes/06c-response/mockups/response.html`.

Обычные модули JS без сборки: `index.html` и `app.css` отдаются по `/` и `/r/{id}`, модули — по `/web/…`. Всё встроено в программу, поэтому после правок клиента нужно пересобрать duet (новая сборка сама заменит работающее ядро, открытые вкладки перезагрузятся).

- `js/main.js` — состояние, маршрут (`/`, `/r/<ревью>`), загрузка, живые обновления, клавиши, дерево, строка состояния, всплывающее. Настройки (колонки, документ, тема, язык, место в ревью, свёрнутые папки) — в `localStorage` с приставкой `duet:`.
- `js/view.js` — отличия ядра в HTML: код (одна и две колонки, свёрнутые куски), документ (`docUnits`: блоки старой и новой версии, связанные общими строками и правками, — единицы «было / стало / новое»). Ничего не пересчитывает.
- `js/markdown.js` — блоки markdown и текст внутри них; подсветка правок переносится из строк в текст и не пересекает теги.
- Места в исходнике: отрисовка помечает каждый кусок текста `data-p="n12.5"` (сторона `o` — база, `n` — текущая; строка с 0; символ строки). По этим пометкам `js/anchors.js` переводит выделение в байты текущей версии (как их хранит ядро), а выделение удалённого — в точку, где оно было, и цитату «было».
- `js/comments.js` — карточки (под абзацем, строкой кода или строкой двух колонок), окно комментария, отметки текста (CSS Custom Highlight API — текст не оборачивается), своё выделение одной фигурой и правки в несколько строк одной фигурой (SVG под текстом). Родного выделения в тексте файла нет: `main.js` гасит нажатие мыши и сам следит за ней — поэтому плашки браузера не появляются.
- Окно правки (`main.js`, `S.edit`; `js/edit.js`) — `#ewrap` поверх `.main`, справа от дерева. Под прозрачной textarea — подсветка исходника по строкам (`editLinesHTML`, номера строк — CSS-счётчик), переносы у них одинаковые. Строится один раз на открытие, перерисовки экрана под ним его не трогают. Место и выделение из чтения — `anchorOf` и `editSelection`. Пока окно открыто, ядро знает `editing` (снимается и при закрытии вкладки, `sendBeacon`). `ReviewView.locked` говорит, почему менять нельзя; `fromDisk` — подсказка «поменяли на диске».
- Окно ответа (`main.js`, `S.resp`) — тот же основной экран в режиме ответа: `#app.rmode` делает из `.main` окно справа от дерева (`#rhead`, `#rfoot`), отличия берутся с `mode=response`, комментарии — на местах в версии из ответа (`resp` у комментария, `shownComments` в `js/comments.js`). Под окном помнится место чтения (`S.resp.back`): туда возвращаемся при закрытии и отклонении.
- `js/syntax.js` — подсветка синтаксиса по словам, состояние переносится между строками.
- Вид (шаг 7a) — `js/look.js`: настройки панели «Вид» (характер, цвета правок, схема, шрифт, размер, края, клавиши на кнопках, язык), значения по умолчанию, цвета правок как переменные CSS (`paint`) и карточка (`panelHTML`). `main.js` хранит выбор в `localStorage` под именем настройки (`duet:char`, `duet:pal`…), ставит классы и переменные на `body` (`applyTheme`) и перерисовывает текст на том же месте, если поменялась раскладка (шрифт, размер, края, язык). Содержимое файла лежит в `.page` — это лист и рамка; одна колонка документа стоит посередине (`--left`). «Сочный» и «яркий» — классы `ch-juicy`, `ch-bright`: дымка `.haze` в `.main`, градиент слов — `#gwa`/`#gwd` в `index.html`, поэтому каждая правка рисуется своим контуром (`shapeMarks`). Макет — `docs/changes/07-look/mockups/look.html`.
- Чтение в одну колонку (шаг 7b). `renderDoc` помечает пару «было / стало» (`.was.old` спрятано над `.chg.hasold`), удалённое без замены (`.was.gone` с чертой `.gonebar`, соседние — одним куском), раскрытые (`.was.open`, по `data-o` из `S.opened`) и слитые с соседями (`jn` / `jp`, в двух колонках — на `.c`). `main.js`: клик и `za`/`zR`/`zM` (`toggleOld`, `allOld`). Движение — только CSS-переходы по классу `open`: блок правки внутри `.was` лежит в сетке `.gx` (строка 0fr ↔ 1fr), поэтому высота, отступы и прозрачность едут вместе, а повторный клик плавно разворачивает движение; без движения — `instant` (класс `noanim` на `#sc`), «до» с комментарием раскрыто всегда (`applyPins` после `placeCards`, класс `pin`). Фокус по блокам: `markBlocks` помечает куски текста блоком агента (`data-blk`, кусок через несколько блоков — по абзацам), `paintFocus` ставит `fcur` текущему, `body.focus` приглушает остальное; `j`/`k` — `moveFocus`.
- `js/tree.js` — дерево файлов; `js/i18n.js` — тексты на русском и английском; `js/util.js` — мелочи (места подсветки из байтов UTF-8 в символы).

Тесты клиента без браузера: `node --test server/webtest`. В браузере клиент проверяется вручную: отдельная папка данных и порт (`DUET_HOME`, `DUET_PORT`), ревью от «агента» через `DUET_SESSION`, `DUET_AGENT`, `DUET_PID`.

## Сборка и тесты

```sh
go test ./...                              # из корня репозитория
node --test server/webtest                 # клиент (нужен Node.js)
./install.sh                               # поставить duet, скилл и хуки (или по ссылке: INSTALL.md)
```

Тесты `app/` собирают настоящую программу и запускают её в отдельной папке данных и на свободном порту. С `-race` медленный тест скорости отличий в `core/` не проходит: гоняйте `-race` для `./server/ ./app/`.

Проверка жестов выделения в Chrome (нужны установленный Chrome, запущенный duet с ревью и `puppeteer-core`):

```sh
node server/browsertest/selection.mjs /путь/к/puppeteer-core/lib/esm/puppeteer/puppeteer-core.js
```

Проверка меняет только DOM отдельной вкладки и системный буфер обмена. Файлы ревью не меняет. Границы слов и расширение диапазона — `server/web/js/selection.js`.
