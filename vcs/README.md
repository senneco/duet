# Сбор изменений репозитория

Пакет `vcs` читает рабочую копию и возвращает снимок. Поддержка git встроена. Здесь нет выбора ревью, изменения текущих версий или разрешения полного принятия. Сквозная интеграция реализована в `core/repository.go` (7p2); запуск внешних программ — `Executable` и `Registry` (7p3). Требования: `docs/specs/vcs.md`.

## Контракт

`Provider` предоставляет три операции только для чтения:

- `Detect(ctx, dir)` — корень, название провайдера и идентичность **отдельной рабочей копии**. `nil, nil` означает достоверное отсутствие репозитория; ошибка не равна отсутствию.
- `State(ctx, workspace)` — неизменяемый идентификатор текущего коммита, непустой отпечаток состояния, полный список незакоммиченных изменений и диагностика. Отпечаток меняется при смене коммита, списка и содержимого индекса. Пустая revision допустима только для рабочей копии без первого коммита.
- `Original(ctx, workspace, revision, path)` — содержимое именно указанного коммита. Результат различает `text` (в том числе пустой), `absent` и `unsupported`. Ошибка чтения возвращается отдельно. Нельзя заменять её отсутствием файла или исходником агента.

Пути внутри снимка — относительные корню, UTF-8, с `/`, без выхода через `..`. Абсолютный путь и идентичность рабочей копии находятся в `Workspace`. `PreviousPath` связывает распознанное переименование с прежним путём; оба пути попадают в снимок. Диагностика содержит `code`, `message` и известный `path`; пустой путь означает общую ошибку. `mode` у содержимого — обычный режим файла (`100644` / `100755`); неподдерживаемый объект может сохранять свой режим для диагностики.

`Snapshot.Protocol` равен 1, структуры имеют JSON-поля. Транспорт внешних процессов использует ту же версию протокола; регистрация и запуск описаны ниже.

## Сбор

```go
snapshot := vcs.Collect(ctx, vcs.Git{}, cwd, materialPaths)
```

`materialPaths` — объединение известных файлов ревью и явно переданных материалов; относительные пути считаются от cwd. Они **дополняют** обязательные изменения. Явно переданный игнорируемый файл читается. Материалы вне корня возвращаются в `External`; их исходниками занимается ядро по правилам вне репозитория.

Сбор читает весь корень, включая соседние каталоги. Идентичность git основана на каноническом корне рабочей копии: git worktree не объединяются, а запуск через ссылку на тот же каталог не создаёт другую идентичность. Переменные окружения `GIT_*` вызывающего процесса не могут подменить индекс или корень. Git вызывается без необязательных блокировок и без fsmonitor; внешние фильтры содержимого не запускаются.

Текущая версия всегда с диска. Путь остаётся в наборе при расхождении индекса с коммитом, даже если диск уже совпал с коммитом. Индекс не показывается как отдельная версия. Изменения относительно других веток не собираются.

Два чтения исходников и текущего содержимого окружены тремя чтениями состояния, затем повторно проверяется рабочая копия. При расхождении — новая попытка, всего не более трёх. Если согласованность не достигнута, `Consistent=false` и есть причина `changed`. Это проверка наблюдаемой стабильности: она не блокирует чужие процессы и не обещает неизменность после возврата. Перед новым уведомлением о полном принятии ядро запускает новый сбор.

`Complete()` относится только к снимку: согласованность и отсутствие диагностик. Это ещё **не полнота ревью**. Конфликты принадлежности, применение версий, сохранение неполноты в ревью и запрет сообщения «всё принято» обеспечивает `core/repository.go`.

Бинарные файлы, текст не в UTF-8, ссылки, подмодули, вложенные самостоятельные репозитории и изменение режима файла возвращают причины неполноты. Через ссылки и внутрь вложенных репозиториев сбор не переходит. Неразрешённые конфликты и флаги индекса, скрывающие изменения, также диагностируются. Доступные материалы остаются в `Entries`; их нельзя принимать за полный результат при ошибке.

## Проверка

`go test ./vcs` создаёт временные репозитории. Проверяются соседние каталоги, git worktree, подготовленные изменения с отличающимся диском, удаления и переименования, необычные имена, пустые файлы, игнорирование, отсутствие первого коммита, ошибки, неподдерживаемые объекты и ограниченный повтор при смене коммита, списка, индекса и текста. Проверяется, что сбор не переписывает индекс и не меняет HEAD. Тестовый провайдер проверяет общий контракт без запуска внешнего плагина.

## Внешние плагины (7p3)

`Executable` запускает отдельный процесс через JSON-протокол версии 1, ограничивает время и объём вывода, проверяет ответы и реализует `Provider`. `Registry` читает явные регистрации в папке данных при каждом сборе. Единственный распознавший каталог внешний провайдер используется вместо встроенного git. Ошибка не допускает молчаливого перехода к другому провайдеру.

Команды `duet plugin add/list/remove/check`, контракт JSON, ограничения, пример и диагностика описаны в [публичном гиде](../docs/vcs-plugins.md). Пример: `go build -o /tmp/duet-example-git ./vcs/example` из корня проекта. `go test ./vcs ./core ./app` проверяет настоящий процесс, ошибки транспорта, регистрацию, эквивалентность встроенному git и сквозное применение правил ядра.
