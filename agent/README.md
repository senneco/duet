# Агенты: команды, хуки, пробуждение

После 7p1 сбор репозитория и приоритет баз доступны как слой библиотеки и ядра (`vcs/README.md`, `core/README.md`). Команды открытия, завершения и хуки пока его не вызывают: продолжайте явно передавать все материалы задачи и исходники. Полнота всего репозитория для пользователя появится после 7p2.

Как Claude Code и Codex работают с duet. Поведение — `docs/specs/agent-protocol.md`, правила для агента — скилл `app/skill/SKILL.md`.

## Части

- `core/agent.go` — сессии агентов в ядре: подключение и перехват (`Attach`, `Detach`), занятость (`SetBusy`: пока агент занят, комментарии «ожидают», за диском ревью не следим), заход (`WriteCheck` перед записью файла ревью, `Done`, `Stop`), забытые файлы, исходная версия, записка и блоки, доставка (`Deliver`). Заход заканчивается правками **с диска**: агент просто правит файлы, ядро само берёт всё, что в файлах ревью отличается от текущих версий (в том числе изменённое командами).
- `agent/` — протокол поверх ядра: тексты для агента (`text.go`, по-английски, начинаются с `DUET:`), команды агента (`commands.go`), хуки (`hooks.go`), пробуждение и живость (`service.go`).
- `server/agent.go` — HTTP: `POST /api/agent/{submit,connect,done,original,take,status,reviews,web,review-of,hook,wait}`. Обычно ответ — `{text}` для агента или ошибка `{error: "agent", message}`; `web` возвращает `{review}` только после успешной подготовки ревью.
- `app/agent.go` — подкоманды `duet`, `app/install.go` — `duet install`, `install.sh` — сборка и установка.

## Сессия агента

- Номер сессии и процесс агента команда берёт из окружения: Claude Code — `CLAUDE_CODE_SESSION_ID` и `CLAUDE_PID`, Codex — `CODEX_THREAD_ID`. Для тестов — `DUET_SESSION`, `DUET_AGENT`, `DUET_PID`.
- Подключённые сессии отмечены пустыми файлами `~/.duet/sessions/<сессия>`. Хук сначала смотрит пометку: нет — сразу выходит, ядро не трогает. Так хуки стоят во всех сессиях и ничего не стоят.
- Живость: ядро раз в 2 секунды проверяет процессы сессии (сигнал 0). Пропали все — сессия отключена. `SessionEnd` (выход, `/clear`) отключает сразу.
- **Codex** выполняет команды и хуки не в окне, а в общем фоновом процессе `codex app-server`. Он живёт и после закрытия окна и держит сеанс загруженным. Поэтому процессы сессии Codex — окна `codex`: родитель команды или, если команду запустил фоновый процесс, окна `codex`, запущенные в папке агента. Несколько окон в одной папке — сессия жива, пока жив хоть одно. Переменные окружения окна до команд Codex тоже не доходят: у них окружение фонового процесса.

## Открытие из нового чата

`duet reviews [файлы…]` ищет без подключения: с файлами — по точным путям, без них — кандидатов в папке сессии. Пути команда приводит к абсолютным и раскрывает символические ссылки. Поиск не меняет ревью.

`duet web --files файлы…` использует уже подключённое ревью либо находит единственное совпадающее по файлам. Ядро проверяет все перечисленные файлы, подключает сессию и передаёт изменения с диска под одной блокировкой. Браузер открывается после успеха; ошибки подключения, чтения, ограничения правки и неотвеченные комментарии не маскируются главной страницей. Ещё не присланные файлы нужно добавить через `duet submit` с исходными версиями. Что считать материалами текущей задачи, определяет скилл; выбор по путям и ограничения гарантирует код.

В обычном терминале `duet web` по-прежнему открывает список; из неподключённой сессии возвращает подсказку с найденными ревью. Проверка двух чатов в Chrome:

```sh
go build -o /tmp/duet-web-check ./cmd/duet
node server/browsertest/web-reconnect.mjs /путь/к/playwright-core/index.mjs /tmp/duet-web-check
```

Тест создаёт отдельные данные и порт, рабочие ревью не использует.

## Хуки

Ставятся во все сессии (`duet install`): `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd` → `duet hook claude|codex`.

- `UserPromptSubmit` — агент занят; передать накопленное.
- `PreToolUse` — агент занят. Запись файла ревью (Claude: `Write`, `Edit`, `MultiEdit`, `NotebookEdit`; Codex: пути из `apply_patch`) — `WriteCheck`: начинается заход или запрет (код 2, причина в stderr). Файл в папке агента, которого нет в ревью, duet добавляет. После «прервать» запрещено всё.
- `PostToolUse` — передать новые комментарии и сообщения (`additionalContext`), попросить исходную версию забытого файла, заметить файлы ревью, изменённые командой, когда это запрещено.
- `Stop` — конец ответа агента: заход без комментариев заканчивается сам, без ответов на взятые комментарии — `decision: block`.

## Пробуждение свободного агента

- Claude Code: второй хук на `Stop` — `duet wait claude` с `asyncRewake`. Он держит долгий запрос `/api/agent/wait`; когда свободной сессии есть что передать, печатает текст в stderr и выходит с кодом 2 — Claude просыпается с этим текстом. Новый ждущий сменяет старого. Ядро перезапустилось — ждущий переподключается.
- Codex: ядро само зовёт `codex queue --thread <сессия> --message <текст>`, когда сессия свободна и есть что передать.

## Команды агента в Codex

Песочница Codex не пускает команды к ядру (сеть и `~/.duet`). `duet install` кладёт `~/.codex/rules/duet.rules`: команды `duet` идут вне песочницы и без вопроса. Правило срабатывает, только если Codex может разобрать команду: поэтому JSON передаётся **одним аргументом** (`duet submit '{…}'`), а не через heredoc.

## Сборка и тесты

```sh
./install.sh        # собрать duet и поставить: ~/.local/bin/duet, скилл и хуки
go test ./...
```

## Установка по ссылке

- `INSTALL.md` в корне — инструкция для агента, которому владелец дал ссылку на репозиторий: запустить установщик, проверить `duet status`, передать владельцу, что осталось.
- `install.sh` из клона с Go собирает duet, иначе скачивает готовую программу `duet-<os>-<arch>` из выпуска `latest` (без входа или через `gh`, если репозиторий закрытый) и запускает `duet install`.
- `duet install` кладёт себя в `~/.local/bin/duet` (`DUET_BIN`), ставит скилл и хуки в те из Claude Code и Codex, что есть на машине (папка настроек или команда в PATH), включает хуки Codex, если они выключены, и печатает, что сказать владельцу.
- Готовые программы собирает `.github/workflows/release.yml` после каждого обновления main: macOS и Linux, arm64 и amd64, выпуск `latest` переписывается.

Тесты `agent/` — логика хуков и доставки на ядре с настоящим диском; `app/agent_test.go` — сквозные проверки на собранной программе (отдать, разбудить, ответить, забытые файлы, подхват, живость, установка).

Живая проверка (шаг 5f) — в herdr, в песочнице: хуки Claude Code на уровне проекта (`.claude/settings.local.json`), Codex — с отдельным `CODEX_HOME`, своё ядро — `DUET_HOME`, `DUET_PORT`. Фоновый процесс Codex получает окружение окна, которое его запустило: перед проверкой его нужно перезапустить из окна с нужными переменными.
