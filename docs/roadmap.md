## Первая рабочая версия (шаги 3–6)

Входит: Claude Code и Codex, браузер, отличия в одну и две колонки, комментарии с отправкой и окном ответа, принятие файлов, список всех ревью, тема как macOS / тёмная / светлая.

Не входит: остальные настройки вида (характер, палитры, края и т.п.), nvim, herdr.

## Заметки для следующих шагов

### Шаг 1
- Репозиторий: приватный `github.com/senneco/duet`, ветка `main`, push по https (git использует учётку gh; ssh не настроен — нет ключа хоста github.com).

### Шаг 2
- Понятия и главные гарантии — в `docs/vision.md`. Подробные правила и 27 сценариев — в `docs/specs/core.md`. Ход обсуждения — в `docs/changes/02-vision/proposal.md`.
- Ключевые решения: исходная версия файла от агента; один ответ агента, пока он не просмотрен — ничего нельзя отправить или поменять; принять / отклонить ответ; правки владельца (`␣e`, «взять с диска», «вернуть к базе»); «прервать»; статусы комментариев «не отправлен → ожидает → в работе → отвечен / вопрос → решён»; диск всегда совпадает с тем, что видит владелец, duet сам пишет правки владельца.
- **Владелец итог шага 2 не читал** (устал к концу обсуждения). Шаг 3 начать с этого: попросить прочитать `docs/vision.md` целиком и раздел «Сценарии» в `docs/specs/core.md`; `proposal.md` читать не нужно. Поправить по его замечаниям, только потом идти дальше.
- Шаг 3 держать небольшим: вопросы из раздела «Открыто: шаг 3» в `docs/specs/core.md`. Если выйдет много, разбить.
- В репозитории не упоминаем внутренние инструменты работодателя владельца (правило в `AGENTS.md`). История на GitHub переписана, чтобы убрать прежнее упоминание.

### Шаг 3
- Владелец прочитал итог шага 2. Поправки: исходная версия сразу становится базой; когда duet сам пишет на диск, агент получает список изменённых файлов с причиной и перечитывает только их.
- Решения шага — в `docs/specs/core.md` (сценарии 1–43), ход обсуждения — в `docs/changes/03-core-behaviour/proposal.md`.
- Главное: архива и «снять с ревью» нет; файл переходит в новое ревью со всем состоянием; отправить комментарии можно только при подключённом агенте, «ожидает» — только когда агент занят; править нельзя, пока есть «ожидает» или «в работе»; значки файлов в дереве; привязка комментариев с цитатой «было: …»; интерфейс на английском и русском, duet пишет агенту по-английски.
- Шаг 4 начать с раздела «Открыто: шаг 4» в `docs/specs/core.md`. Хуки Claude Code теперь важнее: исходная версия сразу становится базой, и ей нужно верить.
- Владелец не хочет, чтобы агент спрашивал его о том, что duet может показать сам: конфликты и выбор показывать плашками в интерфейсе duet.

### Шаг 4
- Решения — в `docs/specs/agent-protocol.md` (сценарии 44–59), ход обсуждения — в `docs/changes/04-agent-protocol/proposal.md`.
- Главное: на ревью отдаёт агент по просьбе владельца; одна сессия — одно ревью; между заходами агент свободен в терминале, duet будит его сам; исходную версию всегда присылает агент (duet копий не снимает); забытые файлы duet добавляет сам, пока агент подключён; данные в `~/.duet`.
- Должно работать везде: обычный терминал, herdr, приложения Claude и Codex. herdr не обязателен.
- Проверено опытами (Claude Code 2.1.316, Codex 0.166): разбудить свободного агента — Claude фоновым хуком `asyncRewake` на Stop (хук ждёт, выход с кодом 2 будит агента, текст из stderr), Codex — `codex queue --thread <session_id> --message`; комментарии посреди работы — `additionalContext` в PostToolUse (в скилле обязательно сказать, что сообщения `DUET:` от владельца, иначе Claude их игнорирует); PreToolUse видит путь до записи (Claude `tool_input.file_path`, Codex — пути в тексте `apply_patch`, абсолютные); Stop `decision: block` не даёт закончить (Claude показывает это как «Stop hook error», поэтому основной путь — явное «готово» от агента); SessionEnd не приходит при убитом процессе — живость проверять самому; Esc не убивает запущенную агентом команду. В хуках есть `session_id` и переменные окружения терминала (`HERDR_PANE_ID`).
- Не проверено: приложения Claude и Codex (GUI). Проверить на шаге 5.
- Песочница опытов: `/tmp/duet-exp` (отдельный `CODEX_HOME`, настройки владельца не тронуты).

### Шаг 5 (разбивка)
- Владелец просит шаги поменьше и попроще: большой шаг трудно держать в голове. Шаг 5 разбит на 5a–5f.
- Ответы владельца, нужные дальше: `duet web` (или короткое `duweb`) — агент запускает, и открывается страница в браузере (5e); постоянный адрес желателен, но не критичен (5e); если duet был выключен, а файлы меняли — сделать логично, на усмотрение (5d); отличия по словам — как на свежих скриншотах прошлой версии: слова собираются во фразы, предложения, абзацы в зависимости от объёма правки (5c).

### Шаг 5a
- Код ядра — `core/`, устройство в `core/README.md`. Go ставится через brew.
- Комментарии вставлять в `Review`/`File` ядра; блокировки уже есть: `ErrUnviewedResponse`, `ErrAgentWorking`. Ответ без правок файлов пока не создаётся (сценарий 62) — на шаге 5b ответ с одними ответами на комментарии тоже должен появляться.
- Агент присылает изменения уже существующих файлов только ответом (`AgentStart` → `AgentFinish`); `AddFiles` добавляет только новые для ревью файлы.

### Шаг 5b
- Решения — в `docs/specs/core.md` (сценарии 63–67), ход — в `docs/changes/05b-comments/proposal.md`.
- Главное: «принят» = текущая совпадает с базой и нет комментариев «отвечен»; ответ в ветке ждёт `␣s`; «убрать вопрос» = «решён».
- Отличия по строкам (Майерс) уже есть в `core/diff.go`, ими пользуется привязка комментариев. На шаге 5c строить отличия по словам поверх них.
- В ядре появились подключение агента (`Connect`/`Disconnect`), `Send`/`Take`, ответы в `AgentFinish`, `Interrupt` (без диска), `SetEditing`. Незаконченный заход копится в `Review.Draft`, пока есть «ожидает».
- Картинки в комментариях — только ссылки в сообщении (`Images`), хранение файлов картинок — вместе с веб-клиентом.

### Шаг 5c
- Решения — в `docs/specs/core.md` (раздел «Отличия», сценарии 68–79), ход — в `docs/changes/05c-diff/proposal.md`. Устройство — в `core/README.md`.
- Ядро отдаёт готовые куски (`FileDiff`, `ResponseDiff`): `same` / `changed` с подсветкой внутри строк / `deleted` / `added`. Клиенту считать ничего не нужно.
- Владелец не хочет «дыр»: между изменёнными словами не должно оставаться неподсвеченных пробелов. Это проверяется тестом на случайных правках.
- ИИ для сборки правок, пометка «перенесено» — в `docs/later.md`.
- Для шага 7 (вид), по красным стрелкам на старых скриншотах: удалённый текст не зачёркивать (трудно читать) — красный фон, добавленный — синий; в двух колонках удалённые строки слева тоже на красном фоне, штриховка пустого места справа — правильно.
