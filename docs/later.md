# Отложено и отклонено

- **Оглавление по заголовкам (outline).** Отклонено в прошлой версии: спорит с блоками агента — две навигации по одному файлу. Вернуться, если в длинных файлах без блоков не хватит навигации.
- **Собственные уведомления.** Отклонено в прошлой версии: оповещения уже есть у терминала и приложения агента.
- **Размытие (стекло) под панелями.** Отклонено в прошлой версии: панели и окна мигали.
- **«Отменить» и «Повторить» в окне ответа.** Отклонено на шаге 2: владелец ими не пользовался. Вместо них есть «отклонить ответ».
- **Отозвать один отправленный комментарий.** Отклонено на шаге 2: лишняя сложность. Есть «прервать» целиком или новый комментарий «не надо».
- **Отклонить ответ по одному файлу.** Отложено на шаге 2: ответ отклоняется только целиком. Вернуться, если часто нужно отклонить один файл из нескольких.
- **Вернуть к базе часть файла.** Отложено на шаге 2: только файл целиком.
- **Закрывать комментарии руками.** Отклонено на шаге 2: комментарии закрываются сами, когда файл принят.
- **Смотреть и принимать ответ, пока агент работает дальше.** Отклонено на шаге 2: появляются цепочки ответов и двоякость, к какой версии относится комментарий. На шаге 6c сделано только для одного случая: агент работает поверх ответа после отправки из окна — тогда ответ можно смотреть и принять, а продолжение вливается в него или становится новым ответом.
- **Просмотр старых версий в интерфейсе.** Отложено на шаге 2: ядро хранит всю историю, но в интерфейсе только «база → текущая» и окно ответа.
- **Несколько агентов в одном ревью одновременно.** Отклонено на шаге 2: в ревью работает не больше одного агента.
- **Снять файл с ревью.** Отклонено на шаге 3: непринятые правки остались бы на диске мимо ревью и попали бы, например, в коммит. Агент может только удалить файл.
- **Архив ревью.** Отклонено на шаге 3: ревью всегда в списке. Вернуться, если список станет слишком длинным.
- **Один файл в нескольких ревью.** Отклонено на шаге 3: два агента правят один файл, появляются цепочки ответов. Файл переходит в новое ревью целиком.
- **Отправлять комментарии без подключённого агента.** Отклонено на шаге 3: непонятно, кто и чего «ожидает». Без агента duet сразу говорит «нет агента».
- **Автоматически прерывать работу, когда агент пропал.** Отклонено на шаге 3: при прерывании перезаписываются файлы на диске, это делается только по команде владельца.
- **Агент сам отдаёт работу на ревью без просьбы.** Отклонено на шаге 4: на ревью отдают по просьбе владельца, дальше в той же сессии — само.
- **duet сам снимает копию файла до правок агента во всех сессиях.** Отклонено на шаге 4: исходную версию присылает агент.
- **Одна сессия агента ведёт несколько ревью.** Отклонено на шаге 4: одна сессия — одно ревью.
- **duet сам нажимает Esc агенту при «прервать» через herdr.** Отложено на шаг про herdr.
- **ИИ собирает правки в цельные куски.** Отложено на шаге 5c: сначала программная разница, ИИ — отдельным шагом после веб-клиента, когда будут видны живые примеры, где правила не справляются. Условие: ИИ может только склеивать правки в более крупные куски, но не прятать их; если его вариант не покрывает всё, что нашла программа, ядро его отбрасывает. Кто делает: проще всего сам агент в конце ответа, или фоновый вызов модели; сначала показывается обычная разница, уточнённая подменяет её, когда готова.
- **Пометка «перенесено».** Отложено на шаге 5c: переставленный без правок кусок пока показан как «удалено здесь, добавлено там».
- **Комментарии в коде как текст.** Отложено на шаге 5c: перенос строк в многострочном комментарии кода сейчас подсвечивается (в коде перенос строки — настоящее изменение). Вернуться, если такой шум будет мешать.
- **Сверять с диском все ревью сразу после запуска duet.** Отклонено на шаге 5d: часто duet запускают ради одного ревью, остальные не нужны. Ревью сверяется, когда его открыли или в нём что-то происходит.
- **Следить за диском в ревью, принятом целиком.** Отклонено на шаге 5d: работа закончена, файл живёт дальше в других задачах и коммитах, пометки были бы шумом.
- **Запускать ядро при входе в систему.** Отклонено на шаге 5e: ядро запускается само по любой команде duet. Вернуться, если часто нужно открыть duet, когда ни один агент его ещё не звал.
- **Отдельное окно-приложение без вкладок и адресной строки.** Отклонено на шаге 5e: обычная вкладка работает в любом браузере.
- **duet сам открывает вкладку, когда агент отдал ревью.** Отклонено на шаге 5e: агент пишет ссылку в чат, вкладку открывает `duet web` по просьбе владельца.
- **`duet web` переключает уже открытую вкладку вместо новой.** Отклонено на шаге 5e: владелец выбрал всегда новую вкладку.
- **Живость агента в приложении Codex.** Отложено на шаге 5f: Codex выполняет сессии в общем фоновом процессе, который живёт и после закрытия окна, а в приложении нет окна `codex` в терминале. Сейчас отключение там — только при выходе из сессии. Вернуться, если в приложении Codex агенты будут «висеть» подключёнными; путь — протокол фонового процесса Codex (`thread/closed`).
- **Запрещать команды агента, которые меняют файлы ревью, до выполнения.** Отложено на шаге 5f: команду нельзя надёжно разобрать заранее. Сейчас duet замечает такую правку сразу после команды и просит вернуть, а файл помечен «изменён на диске».
- **Открыть репозиторий для всех.** Отложено на шаге 5f: пока репозиторий закрытый, установка по ссылке работает только у тех, у кого есть к нему доступ (через GitHub CLI). Открыть, когда duet будет готов для других пользователей: установщик уже умеет скачивать без входа в GitHub.
- **Удаление duet одной командой.** Не делали на шаге 5f: не просили. Сейчас — убрать хуки duet из настроек агентов, скиллы `duet` и `~/.local/bin/duet`.
- **«Изменён на диске» в интерфейсе: «взять с диска», «перезаписать», плашка с отличиями.** Отложено на шаге 6a на продумывание: владельцу непонятен сам случай, поведение кажется слишком сложным. Сейчас ядро по правилам шага 5d помечает такой файл и не даёт его принять, клиент показывает пометку и причину отказа, но выхода из этого состояния в интерфейсе нет. Вернуться до того, как duet станет ежедневным инструментом (шаг 6c или отдельный шаг): возможно, упростить само правило в ядре.
- **Комментарии в панели справа.** Отложено на шаге 6b: владельцу понравились и «в тексте», и панель со списком всех комментариев файла; сделали только «в тексте». Вернуться переключателем в настройках вида (шаг 7 или позже). Как выглядела панель — в первом варианте макета шага 6b (`docs/changes/06b-comments/mockups/comments.html#s=4&l=panel`).
- **Записка агента «начните отсюда».** Отклонено на шаге 6a: владельцу непонятно, что это и как её увидеть. Вместо неё агент отмечает файл, с которого начать, и ревью открывается на нём. Поле `note` в протоколе осталось для агента, который подхватит ревью, но скилл его больше не предлагает.
