Дополнение шага 7p: [полнота ревью и плагины](vcs.md) определяет отображение конфликтов, неподдерживаемых файлов и неполноты ревью. Это согласованные требования для реализации на шагах 7p1–7p3.

Записано на шагах 6a (чтение и принятие), 6b (комментарии), 6c (окно ответа), 6d (правки владельца), 7a (панель «Вид») и 7b (чтение в одну колонку: «как было» по клику, соседние правки, фокус по блокам). Ход обсуждения — в `docs/changes/06a-reading/proposal.md`, `docs/changes/06b-comments/proposal.md`, `docs/changes/06c-response/proposal.md`, `docs/changes/06d-owner-edits/proposal.md`, вид — макет D `docs/changes/06a-reading/mockups/d-keyboard.html`, комментарии — `docs/changes/06b-comments/mockups/comments.html`, окно ответа — вариант E `docs/changes/06c-response/mockups/response.html`, правка — вариант C `docs/changes/06d-owner-edits/mockups/edit.html`, вид и панель «Вид» — `docs/changes/07-look/mockups/look.html` (ход — `docs/changes/07-look/proposal.md`). Устройство — `server/README.md`, раздел «Веб-клиент». Правила ядра — в `docs/specs/core.md`, адрес и живые обновления — в `docs/specs/server.md`.

## Вид

- Вид — по макету D «Клавиатура»: почти без кнопок, строка состояния внизу (режим, файл, «принято N/M», агент, место в файле, подсказка `␣`), меню `␣` всплывает снизу, документ шрифтом с засечками. Меток «было / стало / новое» на полях нет (шаг 7a).
- Всё, что про отображение, — сверху справа: «документ / исходник», «одна / две колонки» и «вид `,`». В меню `␣` только действия.
- Документ в одну колонку стоит посередине области документа (между деревом и правым краем).

## Панель «Вид» (шаг 7a)

- Кнопка «вид `,`» сверху справа; карточка выпадает поверх текста. `,` открывает и закрывает, Esc и клик мимо закрывают. Пока карточка открыта, буква переключает настройку на следующее значение по кругу, остальные клавиши (прокрутка) работают как обычно.
- Настройки (по умолчанию — выделенное):
  - характер `h`: тихий / **обычный** / сочный / яркий;
  - цвета правок `c`: Сияние / Море / Лес / Закат / **Классика** (пара «новое / убранное» и акцент интерфейса; Классика — зелёный и красный, как в GitHub; Сияние — синий и красный);
  - схема `t`: **как macOS** / тёмная / светлая;
  - шрифт `f`: **с засечками** / без засечек;
  - размер текста документа `s`: мельче / **средний** / крупнее;
  - края текста `e`: **без краёв** / лист / рамка;
  - фокус по блокам `b`: **нет** / да (шаг 7b);
  - клавиши на кнопках `p`: **да** / нет (подписи клавиш на кнопках верхних строк);
  - язык `l`: RU / EN (по умолчанию — язык системы).
- **Характер** — сила подсветки правок. Тихий — бледнее; обычный — ровные подложки, изменённые слова ярче блока; сочный — насыщеннее, подложка тает к правому краю, у левого края прямая полоса (левые углы не скруглены), изменённые слова — градиентом по всей фигуре правки, за текстом лёгкая дымка, неподвижная при прокрутке; яркий — как сочный, сильнее, полосы и слова слегка светятся.
- **Лист и рамка:** содержимое файла лежит на листе (или в рамке); в документе в одну колонку правки идут от края до края листа, в двух колонках — от края до края своей колонки.
- Комментарии в коде на подсветке правки — светлее, чтобы читались.
- Выбор запоминается в браузере и сразу действует во всех открытых вкладках. Шрифт, размер, края и язык перерисовывают текст на том же месте.
- То же действует в окне ответа.

## Список ревью

- По адресу `http://duet.localhost:4848` — все ревью, новые сверху. У каждого: название, когда создано, «принято N из M», агент (не подключён / ждёт / занят / работает), непросмотренный ответ, «принято целиком».
- «Занят» — агент подключён и чем-то занят в чате, но комментарии не берёт. «Работает» — у него есть комментарии «в работе».
- `j`/`k` или стрелки — выбрать ревью, Enter или клик — открыть.

## Ревью: дерево файлов

- Слева дерево: по папкам и алфавиту, папки сначала, папки сворачиваются по клику. Общая для всех файлов часть пути не повторяется; цепочка папок без файлов — одной строкой («server/web/»).
- Значки — по `docs/specs/core.md`, «Файлы в дереве». Агент работает по комментариям к файлу — вместо кружка змейка: шесть точек 2×3, огонёк бежит по часовой стрелке.
- Под открытым файлом — его блоки агента с важностью ⇈ ↑ ↓; клик ведёт к началу блока. Клик по названию открытого файла сворачивает и разворачивает его блоки.

## Открытие ревью

- Ревью сверяется с диском с видимым прогрессом.
- Первым открывается файл, который агент отметил начальным, если его ещё не открывали. Иначе — первый по дереву файл, который ещё не открывали.
- Если владелец уже был в ревью в этом браузере — тот же файл и то же место.
- Открытый файл перестаёт мигать во всех вкладках.

## Файл: отличия «база → текущая»

- Отличия считает ядро, клиент их только рисует.
- **Подсветка.** Светлый фон собирает правку в блок. Тёмным подсвечен текст, которого не было (синий) или который убрали (красный): изменённые слова в строке, а строка или абзац, новые или удалённые целиком, — весь их текст. Так новая строка среди изменённых видна сразу. Удалённое не зачёркивается. Правка, которая переносится на несколько строк или разбита разметкой (жирное, ссылка, код), подсвечена одной цельной фигурой со скруглёнными углами.
- **Одна или две колонки** — одна настройка для всех файлов, запоминается в браузере (`␣v`). Две колонки: слева база, справа текущая, пустые места заштрихованы. Одна колонка: см. «Чтение в одну колонку» ниже.
- **Документ и исходник.** Markdown (и файлы без расширения — страницы Вики, тикеты) по умолчанию показан документом с подсветкой правок в отрисованном тексте; `␣m` — исходник, выбор запоминается. Код и обычный текст — всегда исходником с номерами строк.
- В документе правка показана единицей «было / стало»: старые и новые блоки (абзацы, пункты, таблицы), которых касается правка. Если в блоке только дописаны слова — один новый блок, без «было». Блок кода внутри документа, где поменялись отдельные строки, показан один раз, построчно. Если поменялись только пустые строки — маленькая пометка «добавлена / удалена пустая строка».
- **Подсветка синтаксиса** — в коде и в блоках кода внутри markdown, правки поверх неё заметны.
- **Неизменённый текст.** Документ и обычный текст — целиком. В коде неизменённые куски свёрнуты в «ещё N строк» (вокруг правок по три строки), клик разворачивает. Файл без правок — целиком.
- Пока база — исходная версия от агента, над базой видно «до задачи» и откуда она взята.
- Новый файл без базы и удалённый файл — обычным текстом с надписью «новый файл» / «файл удалён».
- Файл, перешедший в другое ревью, — надпись со ссылкой на то ревью.
- Изменение файла на диске duet сам берёт правкой владельца и коротко показывает «… поменяли на диске». Пометка «изменён на диске» бывает, только пока это изменение ждёт (есть непросмотренный ответ или открыт редактор).
- У правого края — карта правок; клик по ней прокручивает файл.

## Чтение в одну колонку (шаг 7b)

- **«Как было» по клику** — только в документе (отрисованный markdown) в одну колонку; в исходнике и коде удалённые строки видны как раньше. По умолчанию видно только новое; у блока, у которого есть старая версия, слева на полях красная точка. Клик по блоку (или по точке) раскрывает старую версию над ним: она плавно выезжает вверх и стоит вплотную, без разрыва; ещё клик сворачивает её вверх. Блок, по которому кликнули, всё это время стоит на месте — двигается то, что выше. Раскрытым бывает одно «до»: клик по любому блоку документа сворачивает раскрытое, а если у этого блока есть свёрнутое «до» — заодно раскрывает его. Так же с `za` у места чтения. `zR` раскрывает всё, следующий клик всё сворачивает. «До» с комментарием не сворачивается. Двойной клик выделяет слово и ничего не раскрывает; клик по тексту с комментарием выбирает комментарий.
- `za` — раскрыть или свернуть у места чтения (треть экрана сверху), `zR` / `zM` — все в файле сразу, место чтения не сдвигается.
- **Удалённое без замены** — тонкая красная черта «удалено: N абзацев» (соседние удалённые куски — одна черта); клик раскрывает удалённый текст.
- «До», к которому есть комментарий, раскрыто всегда, карточка — сразу после него (у переписанного блока — после нового текста).
- Что раскрыто, помнится, пока открыт файл; другой файл и окно ответа начинаются свёрнутыми.
- **Соседние правки — одним блоком.** Подряд идущие новые куски — одна подложка без щелей; блок, у которого есть «до», и удалённое всегда отдельно. Карточка комментария между ними разрывает подложку. В двух колонках так же по каждой колонке (штриховка тоже), кроме строк «слева старое, справа новое».
- **Фокус по блокам** (настройка в панели «Вид», `b`): когда включён и у файла есть блоки агента, блок, который читаешь, обычной яркости, остальной текст приглушён (и карточки комментариев в нём). При прокрутке фокус следует за местом чтения, внизу файла — последний блок, начало которого видно. `j`/`k` и стрелки ходят по блокам: длинный блок сначала долистывается до конца, потом — следующий; текст до первого блока — тоже остановка. Клик по тексту другого блока или по блоку в дереве переводит фокус на него, `]b`/`[b` — как раньше. В файле без блоков фокус ничего не приглушает, `j`/`k` прокручивают как обычно.
- Всё это действует и в окне ответа, кроме фокуса: блоков агента там нет.

## Принять файл (`␣a`)

- `␣a` или «принять» принимает открытый файл и сразу открывает следующий непринятый по порядку дерева (по кругу). Непринятых нет — файл остаётся открытым, и видно «ревью принято целиком» или что ещё мешает (неотправленные комментарии, вопросы агента, непросмотренный ответ, изменения на диске, агент работает).
- Ядро запретило — duet говорит почему: «есть непросмотренный ответ агента к этому файлу» или «файл изменён на диске, а взять это правкой пока нельзя». Файлы, которых ответ не касается, принимать можно.

## Комментарии

- **Своё выделение.** Выделение текста файла рисует duet: одной цельной фигурой со скруглёнными углами и переходом от синего к фиолетовому. Родного выделения браузера в тексте файла нет, поэтому плашки браузера (например, «Перевести») не появляются. Двойной клик выделяет слово. Копировать — `⌘C` или «Копировать» в меню правой кнопки.
- **Меню при выделении** — маленькое, рядом с выделением: «Комментарий `gc`».
- **Окно комментария** — рядом с выделением, без цитаты (выделение остаётся видимым). `⌘Enter` — сохранить, Enter — новая строка. Esc в пустом окне закрывает его, с текстом — «Удалить комментарий?» («Удалить» / «Отмена»). Картинки — `⌘V` или перетаскиванием.
- Без выделения `␣c` или «комментарий» сверху — комментарий ко всему файлу, окно в начале файла.
- **Удалённый текст** тоже можно выделить и прокомментировать. Комментарий висит там, где был этот текст, с цитатой «было»: в двух колонках — на заштрихованном месте справа или под парой «было / стало», в одной — под удалённым куском.
- **Карточки — в тексте**: сразу под абзацем, строкой кода или строкой двух колонок, к которым относятся; ко всему файлу — в начале файла. Если абзац внутри большого нового куска, кусок разрезается после абзаца, и карточка стоит прямо под ним (в двух колонках — когда слева штриховка; если слева старый текст, карточка под всей парой, иначе колонки разъедутся). У карточки номер, статус (не отправлен, ожидает, в работе, отвечен, вопрос), цитата «было: …» и «текст изменён», если место переписали, и вся ветка. Решённые не видны. Одинаково в документе и исходнике, в одной и двух колонках.
- **Отметка в тексте** — подчёркивание цветом статуса; клик по тексту или карточке выбирает комментарий: текст подсвечен, у карточки видны действия.
- **Действия выбранного комментария:** свой неотправленный комментарий или ответ — «править» (Enter) и «удалить» (`x`, с вопросом); «отвечен» — «не согласен, ответить» (Enter); «вопрос» — варианты кнопками и цифрами, «свой ответ», «убрать вопрос» (`x`). Ответ владельца и выбранный вариант — «не отправлен», уходят по `␣s`.
- **В дереве** у файла — число веток, доступных в основном просмотре, синее, если среди них есть вопрос агента. Скрытые отвеченные ветки не учитываются. Нажатие на число открывает файл и переводит к следующему комментарию ниже места чтения; после последнего — к первому. Повторные нажатия последовательно обходят комментарии по документу.
- **Отправка.** В строке состояния — «не отправлено: N · ␣s». `␣s` или клик по нему сразу отправляет всё неотправленное ревью, без подтверждения (в окне ответа — только написанное в окне). Нет агента — «нет агента» и ссылка, по которой агент подхватит ревью, с кнопкой «копировать». Непросмотренный ответ или другой запрет ядра — duet говорит почему.
- **Прервать.** Пока есть «ожидает» или «в работе» — «прервать `␣u`» рядом со статусом агента и в меню `␣`. Сначала подтверждение. Пока агент останавливается — «Агент останавливается…», через 10 секунд — «Вернуть файлы всё равно». Агент пропал посреди работы — полоса над файлом с кнопкой «Прервать».
- Расположение комментариев в панели справа — `docs/later.md`.

## Окно ответа

- **Само не открывается.** Агент прислал ответ — в строке состояния переливается «ответ агента · `␣r`», над затронутым файлом «ответ агента касается файла» и кнопка «ответ агента `␣r`», по затронутым файлам в дереве бежит рябь.
- **Пока ответ не открыт,** в карточках, на которые агент ответил, вместо ответа — «агент ответил — откройте ответ `␣r`», действий у таких карточек нет. Запрет ядра «есть непросмотренный ответ» (принять затронутый файл, отправить, ответить в ветке) — с кнопкой «Открыть ответ» (Enter).
- **Вид (вариант E).** Окно справа от дерева поверх затемнения. Дерево не затемнено и служит навигацией: файлы, которых ответ не касается, приглушены и не нажимаются; файл, который агент создал в ответе, — с пометкой «новый» (в обычном дереве его нет, пока ответ не принят). Шапка окна: агент, время, сколько файлов, на сколько комментариев ответил и сколько вопросов, «отклонить `␣x`», «закрыть Esc», «принять ответ `␣a`». Над файлом — «текущая → ответ». Низ окна: файл N из M, клавиши, «под окном — ваше чтение: файл». В строке состояния режим «ОТВЕТ».
- **Открывается** на открытом файле, если ответ его касается, иначе на первом файле ответа по дереву.
- **Внутри** — отличия «текущая → ответ» по тем же правилам и в тех же режимах, что основной экран (документ/исходник, одна/две колонки — настройки общие). Новый файл — целиком как новый («агент создал файл в этом ответе»), удалённый — целиком удалённым, файл без правок — целиком с пометкой «правок нет — агент только ответил на комментарий», файл, которого владелец ещё не видел, — отличие от исходной версии.
- **Карточки** — на своих местах в версии из ответа, с ответами агента. Можно ответить в ветке, выбрать вариант, убрать вопрос, оставить комментарий к версии из ответа (`gc`, `␣c`; помечен «к версии из ответа»). Всё это «не отправлен».
- **Отправить** (`␣s` в окне, «отправить агенту» в меню `␣`) — без вопросов уходит только написанное в окне; в строке состояния окна «не отправлено N» считает только его. Ответ остаётся непросмотренным, окно открытым, в шапке — «агент работает над вашими комментариями». Вне окна `␣s`, пока ответ не просмотрен, — запрет с кнопкой «Открыть ответ».
- **Пока агент работает поверх ответа** — подсказка «ответ · `␣r`» без перелива и ряби; окно открывается с ответом, каким он был при отправке. Можно читать, писать, отвечать, отправлять и принять; «отклонить» приглушено — когда агент закончит.
- **Агент закончил, а окно открыто** — в окне ничего не меняется (и счётчики в шапке тоже): «Агент закончил — получен ответ» и переливающееся «ответ обновился · открыть заново `␣r`» в шапке и строке состояния. Принять, отклонить, писать и отвечать — только открыв заново; `␣r` или переход к другому файлу ответа открывает окно заново.
- **Принять** (`␣a`) — без вопросов; окно закрывается, открыт тот файл, что был в окне, в обычном виде «база → текущая».
- **Отклонить** (`␣x`) — с подтверждением: правки будут выброшены, файлы на диске вернутся (созданные агентом удалятся), комментарии, на которые отвечал агент, вернутся «не отправлен», написанное в окне удалится (сколько). После — открыт файл, который был под окном, на том же месте.
- **Закрыть** — Esc (когда закрывать больше нечего), `␣r` или «закрыть»; ответ и написанное в окне остаются. Ответ приняли или отклонили в другой вкладке — окно закрывается само.

## Правка владельца (`␣e`) и «вернуть к базе» (`␣b`)

Решено на шаге 6d.

- **`␣e`** или «править» в шапке файла открывает исходник текущей версии как текст (и для markdown) в окне поверх места чтения, справа от дерева — как окно ответа. Моноширинный шрифт, подсветка синтаксиса, номера строк, без vim-клавиш. В строке состояния режим «ПРАВКА», строка и столбец.
- В окне видно то же место, что было на экране, а выделенный текст выделен и в исходнике.
- `⌘↵` сохраняет и закрывает; `Esc` закрывает, а если текст менялся — «Удалить правку?» (Enter — удалить, Esc — вернуться к правке). Другой файл в дереве или `]f` / `[f` — то же, что Esc. Tab — отступ, как в файле; Shift+Tab — убрать.
- После закрытия чтение открывается на той строке, что была вверху окна правки.
- **`␣b`** или «вернуть к базе» в меню `␣` — с вопросом: выбрасываются все изменения после базы, и агента, и владельца, комментарии остаются.
- Нельзя — duet говорит почему: непросмотренный ответ («Открыть ответ»), агент работает («Прервать и править?» — после остановки агента сама открывается правка или вопрос «вернуть к базе»), агент останавливается, файл удалён (для `␣e`), у нового файла нет базы или файл и так равен базе (для `␣b`).
- Закрыли вкладку с открытой правкой — duet снимает «открыта правка».

## Клавиши

- `j`/`k`, стрелки, PageUp/PageDown — прокрутка (при фокусе по блокам `j`/`k` и стрелки — по блокам); `gg`/`G`, Home/End — в начало и в конец.
- `za` — «как было» у места чтения, `zR` / `zM` — раскрыть / свернуть всё.
- `]c`/`[c` — изменения, `]f`/`[f` — непринятые файлы, `]b`/`[b` — блоки агента.
- `␣` — меню действий; `␣a` — принять; `␣v` — колонки; `␣m` — документ/исходник; `?` — все клавиши; Esc — закрыть.
- Комментарии: `gc` — к выделенному; `␣c` — к выделенному или ко всему файлу; `␣s` — отправить; `␣u` — прервать агента; `]n`/`[n` — следующий и предыдущий комментарий; у выбранного — Enter, `x`, цифры вариантов.
- Правка: `␣e` — править, в окне `⌘↵` — сохранить, Esc — закрыть; `␣b` — вернуть к базе.
- Ответ агента: `␣r` — открыть и закрыть окно; в окне `␣a` — принять ответ, `␣x` — отклонить, `]f`/`[f` — файлы ответа, Esc — закрыть.
- Всё, что делается клавишами, можно сделать мышью.

## Тема и язык

- Тема: как macOS (по умолчанию, сразу следует за системой) / тёмная / светлая. Язык: по умолчанию язык системы, переключается RU/EN. Оба — в панели «Вид», выбор запоминается в браузере.

## Живые обновления и скорость

- Всё, что меняется в ядре, видно сразу; открытый файл обновляется на месте, прокрутка не прыгает.
- Ядро остановлено — «duet не запущен», вкладка подключается сама и остаётся на месте.
- Файл на несколько тысяч строк открывается и прокручивается без заметной задержки.

## Не входит

- Комментарии в панели справа — `docs/later.md`.
- Записка агента «начните отсюда», «перезаписать» (вернуть то, что было до изменения на диске), правка отрисованного документа и vim-клавиши в правке — `docs/later.md`.

122. КОГДА владелец возвращается в ревью, в котором уже был в этом браузере, ТОГДА открывается тот же файл на том же месте.
123. КОГДА владелец открыл файл, ТОГДА файл перестаёт мигать в дереве во всех вкладках.
124. КОГДА владелец кликает по папке в дереве, ТОГДА папка сворачивается или разворачивается. КОГДА кликает по названию открытого файла, ТОГДА так же сворачиваются или разворачиваются его блоки.
125. КОГДА владелец кликает по блоку агента или нажимает `]b`/`[b`, ТОГДА файл прокручивается к началу блока.
126. КОГДА владелец переключает одну/две колонки (`␣v`), ТОГДА все файлы во всех ревью показываются так же, и выбор сохраняется после перезагрузки.
127. КОГДА открыт markdown, ТОГДА он показан документом с подсветкой правок. КОГДА владелец нажимает `␣m` или переключатель сверху справа, ТОГДА он показан исходником, и выбор сохраняется.
128. КОГДА открыт код с правками, ТОГДА неизменённые куски свёрнуты в «ещё N строк», вокруг правок видно несколько строк, синтаксис подсвечен. КОГДА владелец кликает по свёрнутому куску, ТОГДА он разворачивается.
129. КОГДА открыт документ или код без правок, ТОГДА он показан целиком.
130. КОГДА база файла — исходная версия от агента, ТОГДА над базой видно «до задачи» и откуда она взята. КОГДА у файла нет базы, ТОГДА он показан целиком обычным текстом с надписью «новый файл».
131. КОГДА владелец нажимает `␣a` и файл можно принять, ТОГДА файл принят и сразу открывается следующий непринятый файл по порядку дерева.
132. КОГДА владелец принял последний непринятый файл, ТОГДА файл остаётся открытым и видно, принято ли ревью целиком или что ещё мешает.
133. КОГДА владелец нажимает `␣a`, а ответ агента касается файла или файл изменён на диске, ТОГДА файл не принимается, и duet говорит почему.
134. КОГДА владелец нажимает `]c`/`[c`, ТОГДА файл прокручивается к следующему или предыдущему изменению. КОГДА нажимает `]f`/`[f`, ТОГДА открывается следующий или предыдущий непринятый файл.
135. КОГДА владелец нажимает `␣`, ТОГДА открывается меню доступных действий с клавишами. КОГДА нажимает `?`, ТОГДА видит список всех клавиш.
136. КОГДА в ядре что-то поменялось, ТОГДА вкладка показывает это сразу, а открытый файл обновляется без прыжка прокрутки.
137. КОГДА тема «как macOS» и система переключила тему, ТОГДА duet сразу переключается тоже.
138. КОГДА владелец выбрал язык, ТОГДА весь интерфейс на этом языке, и выбор сохраняется после перезагрузки.
139. КОГДА открыт файл на несколько тысяч строк, ТОГДА он открывается и прокручивается без заметной задержки.
140. КОГДА среди изменённых строк есть строка, новая целиком, ТОГДА весь её текст подсвечен тёмным, и она отличается от изменённых строк, где тёмным подсвечены только новые слова. Так же для удалённых строк и для абзацев в документе.
141. КОГДА агент работает по комментариям к файлу, ТОГДА вместо кружка у файла бежит по часовой стрелке змейка из шести точек.

### Комментарии (шаг 6b)


**Выделение и новый комментарий**

142. КОГДА владелец выделяет текст мышью, ТОГДА выделение нарисовано одной цельной фигурой, браузер своих плашек не показывает, а рядом с выделением появляется меню «Комментарий `gc`».
143. КОГДА владелец дважды кликает по слову, ТОГДА слово выделено так же.
144. КОГДА есть выделение и владелец нажимает `⌘C` или «Копировать» в меню правой кнопки, ТОГДА выделенный текст скопирован.
145. КОГДА есть выделение и владелец нажимает `gc`, `␣c` или «Комментарий» в меню, ТОГДА рядом с выделением открывается окно комментария, выделение остаётся видимым.
146. КОГДА выделения нет и владелец нажимает `␣c` или «комментарий» сверху, ТОГДА открывается окно комментария ко всему файлу в начале файла.
147. КОГДА в окне комментария владелец нажимает `⌘Enter` или «Сохранить», ТОГДА появляется карточка «не отправлен» под тем местом, к которому комментарий, и текст отмечен. Enter в окне — новая строка.
148. КОГДА в окне комментария владелец вставляет картинку (`⌘V`) или перетаскивает её, ТОГДА картинка видна в окне и потом в карточке.
149. КОГДА владелец нажимает Esc в пустом окне, ТОГДА окно закрывается. КОГДА в окне есть текст или картинка, ТОГДА duet спрашивает «Удалить комментарий?»: Enter или «Удалить» — удалить, Esc или «Отмена» — вернуться к тексту.
150. КОГДА владелец выделяет удалённый текст (слева в двух колонках или красный в одной), ТОГДА комментарий можно оставить так же. В двух колонках его карточка стоит на заштрихованном месте справа, где был этот текст, в одной — под удалённым куском.

**Карточки и ветки**

151. КОГДА у файла есть комментарии, ТОГДА каждый виден карточкой под своим абзацем, строкой кода или строкой двух колонок, с номером и статусом: не отправлен, ожидает, в работе, отвечен, вопрос. Комментарии ко всему файлу — в начале файла. Решённые не видны.
152. КОГДА у текста есть комментарий, ТОГДА текст подчёркнут цветом статуса. КОГДА владелец кликает по нему или по карточке, ТОГДА комментарий выбран: текст подсвечен, у карточки видны действия.
153. КОГДА владелец нажимает `]n` / `[n`, ТОГДА выбирается следующий или предыдущий комментарий в файле, и файл прокручивается к нему.
154. КОГДА выбран свой неотправленный комментарий или ответ и владелец нажимает Enter или «править», ТОГДА он правится в том же окне. КОГДА нажимает `x` или «удалить», ТОГДА он удалён (с вопросом, если в нём есть текст).
155. КОГДА выбран «отвечен» или «вопрос» и владелец нажимает Enter или «ответить», ТОГДА под веткой открывается поле ответа. Сохранённый ответ — «не отправлен» и уходит по `␣s` вместе с остальными.
156. КОГДА агент задал вопрос с вариантами, ТОГДА варианты видны кнопками с номерами и «свой ответ». КОГДА владелец выбирает вариант кликом или цифрой, ТОГДА он становится ответом «не отправлен». КОГДА нажимает `x` или «убрать вопрос», ТОГДА комментарий решён, агенту ничего не уходит.
157. КОГДА комментарий сдвинулся из-за правки текста, ТОГДА в карточке цитата «было: …» и пометка «текст изменён». КОГДА файл удалён, ТОГДА его комментарии — в начале файла как ко всему файлу, с цитатой «было: …».
158. КОГДА у файла есть открытые комментарии, ТОГДА в дереве рядом с ним маленькое число; если среди них есть вопрос агента, число выделено.
159. Всё это одинаково в документе и исходнике, в одной и двух колонках.
160. КОГДА изменённый кусок текста переносится на несколько строк, ТОГДА его подсветка — одна цельная фигура со скруглёнными углами, без разрывов между строками и на жирном, ссылках и коде внутри правки.

**Отправка**

161. КОГДА есть неотправленные комментарии или ответы, ТОГДА в строке состояния видно «не отправлено: N · ␣s».
162. КОГДА владелец нажимает `␣s` или кликает по «не отправлено», ТОГДА все неотправленные комментарии и ответы ревью во всех файлах сразу уходят агенту, без подтверждения: «в работе», если агент свободен, «ожидает», если занят.
163. КОГДА агент не подключён и владелец нажимает `␣s`, ТОГДА ничего не уходит, и duet говорит «нет агента» и показывает ссылку, по которой агент подхватит ревью, с кнопкой «копировать».
164. КОГДА есть непросмотренный ответ агента и владелец нажимает `␣s` или отвечает в ветке вне окна ответа, ТОГДА ничего не уходит, и duet говорит, что сначала нужно просмотреть ответ, и предлагает его открыть.
165. КОГДА ядро запрещает отправку по другой причине (агент останавливается, файл изменён на диске, открыта правка), ТОГДА duet говорит почему.

**Прервать**

166. КОГДА есть комментарии «ожидает» или «в работе», ТОГДА рядом со статусом агента в строке состояния есть «прервать `␣u`», и в меню `␣` — «прервать агента».
167. КОГДА владелец нажимает «прервать», ТОГДА duet спрашивает подтверждение: всё сделанное в этом заходе будет выброшено, файлы на диске вернутся, комментарии вернутся неотправленными. Enter — прервать, Esc — нет.
168. КОГДА владелец прервал, а агент ещё не остановился, ТОГДА видно «останавливается…», комментарии уже «не отправлен» и их можно править, а через 10 секунд появляется «вернуть файлы всё равно».
169. КОГДА агент отключился, а комментарии «в работе» остались, ТОГДА над файлом видно «агент пропал посреди работы» с кнопкой «прервать».

### Окно ответа (шаг 6c)

**Подсказка и открытие**

170. КОГДА агент закончил и прислал ответ, ТОГДА окно не открывается, в строке состояния переливается «ответ агента · `␣r`», над затронутым открытым файлом видно «ответ агента касается файла», по затронутым файлам в дереве бежит рябь.
171. КОГДА есть непросмотренный ответ, ТОГДА в карточках комментариев, на которые ответил агент, вместо текста ответа видно «агент ответил — откройте ответ `␣r`».
172. КОГДА владелец нажимает `␣r` или кликает по подсказке, ТОГДА открывается окно ответа справа от дерева, остальное затемнено. Открыт текущий файл, если ответ его касается, иначе первый файл ответа по дереву.
173. КОГДА агент работает, ТОГДА подсказки `␣r` нет, и `␣r` ничего не открывает.
174. КОГДА владелец пытается сделать то, что ядро запрещает до просмотра ответа (отправить, ответить в ветке, принять затронутый файл), ТОГДА duet говорит «Есть непросмотренный ответ агента» и предлагает «Открыть ответ `␣r`».

**В окне**

175. КОГДА открыто окно ответа, ТОГДА в дереве приглушены файлы, которых ответ не касается; новые файлы из ответа видны с пометкой «новый». Клик по файлу ответа в дереве или `]f` / `[f` открывает его в окне.
176. КОГДА в окне открыт файл, ТОГДА показаны отличия «текущая → ответ» по тем же правилам и в тех же режимах (документ/исходник, одна/две колонки), что и на основном экране, с карточками ответов агента на своих местах. `]c` / `[c` — правки, `]n` / `[n` — комментарии.
177. КОГДА агент создал файл в ответе, ТОГДА он показан целиком как новый, с пометкой «агент создал его в этом ответе». КОГДА агент удалил файл, ТОГДА он показан целиком удалённым. КОГДА файл забытый (владелец его ещё не видел), ТОГДА показано отличие от исходной версии, если она есть.

## Прочитанные ветки после принятия ответа

После принятия ответа отвеченные ветки скрыты в тексте вместе с подчёркиваниями. Ветки с новым неотправленным комментарием владельца и открытые вопросы остаются. История сохраняется. До принятия ответа его ветки доступны в окне ответа.

В окне следующего ответа отвеченные ветки предыдущих принятых ответов также скрыты. Видны отвеченные ветки текущего ответа, встречные комментарии и открытые вопросы.

## Выделение по словам

Второе нажатие на слово сразу выделяет его целиком. Протягивание при удержании второй кнопки расширяет выделение целыми словами в обе стороны, включая переносы строк и встроенную разметку. При смене направления исходное слово остаётся опорой. Отпускание сохраняет диапазон. Обычное протягивание выделяет по символам. Ctrl+C и ⌘C копируют весь выбранный текст; поля редактирования сохраняют собственное копирование.

## Место чтения после ответа

Открытие ответа запоминает файл и положение основного документа. Принятие возвращает к этому месту, независимо от файла и прокрутки в окне ответа. Если выше изменились строки, место переводится в новую версию по отличиям ядра; при удалении текста выбирается ближайшее сохранившееся место. Если прежний файл недоступен, открывается доступный файл ревью. Закрытие и отклонение окна также возвращают к сохранённому месту.

## Геометрия редактора

Область текста редактора повторяет ширину и горизонтальное положение области чтения; в двух колонках — правой колонки. При открытии выделение сохраняется примерно на прежней высоте экрана. Без выделения ориентиром становится текст около середины видимой области. При невозможности точного совмещения из-за границ документа или различий исходника и документа используется ближайшее доступное положение.

В двухколоночном сравнении выделение ограничено стороной, где оно началось. Подсветка и копирование исключают противоположную сторону и номера строк.

При обрыве потока событий вкладка проверяет доступность сервера: отвечает — переподключение к потоку, не отвечает — сервер недоступен. Ошибка сети не считается доказательством остановки ядра. Проверки повторяются автоматически до восстановления потока.

## Схемы Mermaid

В режиме документа блоки `mermaid` отображаются как SVG: блок-схемы, состояния и последовательности, включая русские подписи. Оформление согласовано со светлой и тёмной темами duet. Кнопка увеличения открывает отдельный просмотр с масштабом. Под схемой раскрывается исходник с точными правками и местами для комментариев; в режиме исходника и редакторе сохраняется текст. Ошибка схемы показывает сообщение и исходник, не ломая документ. Библиотека включена в duet, просмотр работает без интернета и внешней передачи текста.

При построчном диффе Mermaid над текстовыми отличиями всегда показывается итоговая схема. Исходный дифф остаётся раскрытым под ней. Окно увеличения центрируется в области экрана; схема располагается по центру области просмотра.

Расстановка карточек комментариев сохраняет выделение в перемещаемых абзацах. Текст ниже существующего комментария можно выделить и прокомментировать так же, как текст выше него.

## Ответ к принятым файлам (шаг 7l)

Если все затронутые ответом файлы приняты или впервые появляются в ответе без базы, версии сразу видны в основном просмотре, без окна ответа и подсказки открыть его. База остаётся прежней. Ответы на комментарии доступны в основном просмотре до принятия файла; вопросы остаются открытыми. Файл и место чтения не переключаются автоматически.

Новые файлы без базы сразу показаны целиком и требуют явного принятия. Если ответ касается существующего непринятого файла, нового файла с исходной базой либо уже есть непросмотренный ответ, сохраняется существующий путь через окно для всего ответа целиком. Принятие в окне всегда только переносит версии вправо. Эти правила уточняют сценарии открытия окна и скрытия отвеченных веток выше.


## Полнота репозитория (7p2)

При ошибке проверки предупреждение сразу показывает файл или операцию и причину. Остальные причины раскрываются в той же панели. Если файл занят, доступна ссылка на соответствующее ревью. Проверку можно повторить после устранения причины. Старый исходник без записи о принятии отображается как обычный файл для чтения и принятия.

После устранения причины требуется новая проверка. Пока есть проблемы, всё ревью не показывается принятым. Открытое окно ответа сохраняет свою версию при новом сборе и предлагает открыть обновлённый ответ заново по существующим правилам.


## Итоговый diff в дереве ревью

Файл, который после проверки совпадает с текущим коммитом и не входит в
набор изменений рабочей копии, сразу попадает в группу «Вне итогового diff».
Группа свёрнута при открытии ревью. Её можно раскрыть, чтобы открыть файл
и его комментарии. Тот же статус виден над содержимым файла и в окне ответа.

Действие «Открыть ответ» доступно и когда текущий файл не затронут ответом
или все файлы основного дерева скрыты. В окне ответа видны изменения самого
ответа. Файл с оставшимися изменениями остаётся в основном дереве после
принятия, а новый файл отличим по подписи «В итоговом diff · новый файл».
