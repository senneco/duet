# 7p7. Итоговый diff в ревью

Владелец выбрал вариант Б в [интерактивном макете](mockups/final-diff.html).
После отката файл сразу скрывается из основного дерева. Владелец может
открыть ответ и увидеть сам откат, а также вернуться к файлу и его комментариям.

## Сценарии

1. КОГДА успешная проверка рабочей копии показывает, что файл из ревью
   больше не входит в изменения относительно текущего коммита, ТОГДА duet
   сразу помещает файл в свёрнутую по умолчанию группу «Вне итогового diff».
2. КОГДА по этому файлу есть непросмотренный ответ, ТОГДА команда «Открыть
   ответ» доступна независимо от выбранного файла. В окне ответа видны сам
   откат и ответы на комментарии. Просмотр ответа оставляет файл в группе.
3. КОГДА владелец раскрывает группу и открывает файл, ТОГДА над содержимым
   видна метка «Вне итогового diff», а комментарии доступны по-прежнему.
4. КОГДА файл принят, но всё ещё отличается от текущего коммита, ТОГДА
   файл остаётся в основном дереве, а в просмотре видны оба факта:
   файл принят и входит в итоговый diff. У нового файла сохраняется
   отдельная отметка о создании.
5. КОГДА следующая проверка снова находит изменение этого файла, ТОГДА
   файл возвращается в основное дерево.
6. КОГДА принадлежность к итоговому diff неизвестна или файл лежит вне
   проверяемого репозитория, ТОГДА он остаётся в основном дереве.
   Диагностика проверки остаётся доступна.

База принятия, версии и комментарии сохраняются. Встроенный git и внешние
провайдеры используют одинаковые правила.

## Проверка

В Chrome проверены откат единственного файла в ревью, скрытие до просмотра
ответа, открытие ответа из верхней панели и доступ к ветке после раскрытия
группы. Тесты ядра проверяют принятие и отклонение ответа, повторное
изменение файла, новый файл и правку в индексе при чистой рабочей версии.
