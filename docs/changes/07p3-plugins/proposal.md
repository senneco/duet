# Внешние плагины (7p3)

Реализация согласованной спеки 7p: `docs/specs/vcs.md`. Повторное согласование поведения не требуется согласно roadmap.

Входит: локальный процесс с JSON-протоколом версии 1, явная регистрация вне репозитория, проверка совместимости, пример и публичный гид. Правила баз и полноты остаются в ядре. Конкретные сторонние интеграции и новый интерфейс не входят.

- КОГДА пользователь регистрирует исполняемый плагин, ТОГДА duet проверяет версию и операции и сохраняет абсолютный путь в своей папке данных.
- КОГДА зарегистрированный плагин распознал рабочую копию, ТОГДА общий сбор использует его через Provider. Если несколько внешних плагинов распознали каталог, возникает явная ошибка; если ни один — используется встроенный git.
- КОГДА процесс недоступен, завис, завершился ошибкой или нарушил протокол, ТОГДА сохраняется неполнота; переход к git или режиму вне репозитория не скрывает ошибку.
- КОГДА репозиторий содержит исполняемый файл без регистрации, ТОГДА duet его не запускает.
- КОГДА внешний плагин сообщает те же данные, что git, ТОГДА правила исходников, принятой базы и полного принятия совпадают.
- КОГДА пользователь проверяет совместимость, ТОГДА выполняются согласованный сбор и проверка структуры ответа; это не доказательство честности списка изменений произвольного плагина.

Проверка: реальные дочерние процессы, ошибки и ограничения транспорта, регистрация и выбор, эквивалентность снимка git, сценарий ядра, полный набор тестов. Плагины — доверенные локальные программы; duet не предоставляет им песочницу.

## Результат

Добавлены `vcs.Executable`, `vcs.Registry`, команды `duet plugin add/list/remove/check`, исполняемый пример поверх git и `docs/vcs-plugins.md`. Ядро использует реестр из своей папки данных; регистрация применяется без перезапуска. Файл регистрации публикуется атомарно, повторный `add` не заменяет существующую запись. Новый интерфейс не добавлялся; уведомление о принятии файлов дополнено причиной неполноты, уже видимой в предупреждении ревью.

Проверено на временных данных:

- `GOCACHE=/tmp/duet-go-cache go test ./...` — весь набор прошёл. Первый ограниченный запуск обнаружил запрет localhost в песочнице; полный прогон выполнен с разрешённым локальным доступом.
- `go vet ./...`, `node --test server/webtest` (35 тестов), `git diff --check` — успешно.
- Новые сценарии `TestPlugin*`, `TestExternalGit*`, `TestRegistry*`, `TestExecutable*` в `vcs`, `core`, `app` прошли также с `-race`.
- Настоящий внешний процесс: эквивалентность снимков встроенному git, пустой файл, новый файл, переименование, удаление и расхождение индекса с диском. Ошибки версии и JSON, неполные ответы, неверные пути и диагностика, ненулевой код завершения, зависание, избыточный вывод и отсутствие программы не скрываются.
- Сквозной сценарий ядра: исходник репозитория важнее переданного, принятая база сохраняется при смене коммита, новый файл обнаруживается, ошибка внешнего процесса блокирует принятие и сохраняется после перезапуска.
- Chrome: внешний провайдер распознан, исчезновение программы при принятии файла показывает причину и блокирует полное принятие; восстановление программы и повторная проверка восстанавливают полноту. Скриншоты просмотрены, ошибок JavaScript нет. Стенд: `server/browsertest/plugin-fixture.go`, `plugin.mjs`.

Плагины остаются доверенными локальными программами, без песочницы; проверка совместимости не доказывает честность произвольной реализации. Конкретная сторонняя интеграция не входит в этот шаг. Рабочие ревью, пользовательская регистрация и материалы `08-terminal` не изменялись. Владелец подтвердил результат и поручил коммит и отправку в main вместе с 7p2. Шаг закрыт.
