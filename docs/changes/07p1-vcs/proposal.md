# 7p1 — сбор изменений и базы

Поведение согласовано владельцем в шаге 7p; реализация разрешена в новом чате без повторного согласования. Основа: `docs/specs/vcs.md` и `docs/changes/07p-vcs/proposal.md`.

## Границы

Входит: общий контракт чтения репозитория, встроенный git, идентичность отдельной рабочей копии, весь корень, подготовленные и неподготовленные изменения, новые неигнорируемые файлы, удаления и переименования, согласованный снимок с ограниченным повтором и явными ошибками. Дополнительные пути не сужают обязательный набор. Сбор ничего не записывает в репозиторий.

В ядре: происхождение базы, исходник из зафиксированного коммита, сохранение явно принятой базы, диагностика неоднозначных старых данных, история исходников без изменения комментариев и текущих версий. Пустой файл, отсутствие и ошибка различаются.

Не входит: вызов сбора при открытии, завершении захода и полном принятии; применение собранных текущих версий через правила ответа; конфликты между ревью и UI неполноты (7p2); регистрация и запуск внешних программ, упаковка и гид плагинов (7p3). До окончания 7p2 полнота пользовательского ревью не гарантируется.

## Проверяемые сценарии

- КОГДА запуск идёт из вложенного каталога, ТОГДА сбор включает изменения соседних каталогов того же корня, но не другого git worktree.
- КОГДА индекс и диск различаются, ТОГДА путь сохраняется в наборе, а текущее содержимое берётся с диска, даже если оно совпало с коммитом.
- КОГДА есть новые и игнорируемые файлы, ТОГДА автоматически включаются только неигнорируемые; явно перечисленный игнорируемый файл тоже читается.
- КОГДА файл удалён или переименован, ТОГДА сохраняется исходник старого пути; отсутствие исходника отличается от пустого файла.
- КОГДА список, коммит или содержимое меняются во время сбора, ТОГДА сбор повторяется ограниченно либо возвращает неполноту.
- КОГДА обнаружен неподдерживаемый объект или ошибка чтения, ТОГДА возвращается причина с известным путём; исходник агента не заменяет ошибку.
- КОГДА исходник агента неверен, ТОГДА база заменяется исходником репозитория без изменения текущей версии, истории и комментариев.
- КОГДА база явно принята, ТОГДА повторный сбор, смена коммита, переподключение и перенос через старый API не заменяют её.
- КОГДА новый исходник совпал с текущим текстом, ТОГДА сбор не принимает файл автоматически.
- КОГДА есть непросмотренный ответ или идёт работа, ТОГДА применение новых исходников откладывается с явной ошибкой, не меняя открытый ответ.
- КОГДА читаются старые данные, ТОГДА известное происхождение восстанавливается по сохранённым признакам, неоднозначное диагностируется; версии и комментарии сохраняются.

Проверка — временные репозитории git, управляемые изменения во время сбора, тесты ядра и регрессионные проверки проекта. Новый интерфейс в 7p1 не добавляется.

## Результат

Реализация и проверка завершены; владелец подтвердил результат и поручил коммит, отправку и переход к 7p2. Шаг 7p1 закрыт. Устоявшиеся требования внесены в `docs/specs/vcs.md` и `docs/specs/core.md`, устройство — в README ядра и нового пакета `vcs`. Следующий шаг — 7p2; сквозная гарантия пока не заявляется.

Обнаружена и учтена неоднозначность старого формата: нажатие «принять» при `Current == Base` не меняло `BaseIsOriginal`. Поэтому у старого исходника нельзя доказать отсутствие явного принятия даже при последующих правках. Миграция сохраняет базу и историю, возвращает происхождение `unknown` и явную причину; новые данные фиксируют такое принятие надёжно. Это предусмотренная спецификацией диагностика, а не догадка о происхождении.

## Проверки

- Временные репозитории: весь корень и соседние каталоги, git worktree, изоляция от переменных окружения git, индекс и диск, игнорирование и явные материалы, удаление и переименование, пустые файлы, необычные имена, отсутствие первого коммита, исходник фиксированного коммита и ошибки.
- Управляемая смена содержимого, списка, индекса и HEAD во время сбора: успешный повтор и остановка после трёх попыток. Общий контракт проверен тестовым провайдером без внешней программы.
- Бинарные файлы, ссылки, вложенные репозитории, подмодули, режим файла и скрывающие изменения флаги индекса дают диагностику. Чтение не переписывает индекс и не меняет HEAD.
- Ядро: замена неверного исходника, отсутствие и пустой исходник, сохранение принятой базы после смены коммита и перезапуска, принятие удаления, идемпотентный повтор, сохранение версий и комментариев, отсутствие автоматического принятия, защита ответа и редактора, отсутствие частичной замены при ошибке, миграция старого формата.
- `go test ./...` — успешно. Для тестовых localhost-серверов потребовался запуск вне сетевых ограничений песочницы.
- `go test -race -skip '^TestDiffFast$' ./...` — успешно. В первоначальном полном прогоне с `-race` сработал только временной порог существующего `TestDiffFast`; обычный полный прогон, включая этот тест, успешен.
- `go vet ./...`, `node --test server/webtest` (35 тестов), `git diff --check` — успешно.
- Chrome, отдельный временный сервер: прямой ответ с комментарием и два новых файла без базы. Сценарий прямого ответа временно адаптирован к установленному Playwright; исходный файл теста не менялся. Оба сценария прошли без ошибок страницы, скриншоты просмотрены. Новый UI в этом шаге не добавлялся.

Владелец разрешил коммит реализации и отправку в репозиторий. `docs/changes/08-terminal/` не изменялась и не включалась в работу.
