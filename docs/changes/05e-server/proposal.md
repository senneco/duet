# Шаг 5e: ядро в фоне, API для клиентов, `duet web`

## Зачем

До сих пор ядро — библиотека, которую видят только тесты. Чтобы владелец открыл ревью в браузере, а агенты слали файлы и брали комментарии, ядро должно постоянно работать в фоне на этой машине и давать клиентам всё нужное: состояние, отличия, действия и живые обновления.

## Решения владельца

- `duet web` **всегда открывает новую вкладку**, даже если вкладка duet уже есть.
- Открываем **вкладкой** в браузере по умолчанию, а не отдельным окном-приложением.
- Ядро запускается **по требованию** и работает до перезагрузки или `duet stop`. Не запускается при входе в систему.
- Адрес: **`http://duet.localhost:4848`**. В адресной строке и истории браузера сразу видно, что это duet.

## Что входит

### Ядро в фоне

- Любая команда duet (`duet web`, с шага 5f — команды агента) сама запускает ядро в фоне, если оно не работает. Терминал не занимается, ничего отдельно запускать не нужно.
- Ядро на машине одно. Если оно уже работает, второе не запускается.
- `duet stop` останавливает ядро. Всё уже сохранено, ничего не теряется.
- Поставили новую версию duet — при следующей команде старое ядро само заменяется новым.

### Адрес

- Список ревью — `http://duet.localhost:4848`, ревью — `http://duet.localhost:4848/r/<ревью>`. Ссылки постоянные: работают после перезапуска duet и перезагрузки.
- Если порт 4848 занят другой программой, duet работает на другом свободном порту и пишет новую ссылку. Это редкий случай, старые ссылки тогда не работают.
- duet доступен только с этой машины: другие компьютеры в сети его не видят, чужие сайты в браузере не могут ни читать, ни менять ревью.

### `duet web`

- Открывает новую вкладку в браузере по умолчанию и пишет ссылку в терминал.
- Если указано ревью, открывается оно, иначе — список ревью. С шага 5f агент сам открывает ревью своей сессии.
- Владелец может запустить `duet web` и сам в любом терминале.
- **Сценарий 47 меняется** (решение владельца на этом шаге): когда агент отдал работу на ревью, duet сам вкладку не открывает. Агент пишет ссылку в чат, а вкладку открывает `duet web`, когда владелец его попросит.

### Живые обновления

- Всё, что меняется в ядре (прислал агент, действие в другой вкладке, изменение на диске, подключение и отключение агента), видно во всех открытых вкладках сразу, без перезагрузки.
- Ядро остановлено — открытая вкладка показывает «duet не запущен» и подключается сама, когда ядро снова запущено. Вкладка остаётся там же, где была.
- Владелец открыл ревью — ревью сверяется с диском с видимым прогрессом. Дальше, пока ядро работает, duet следит за диском этого ревью (правила шага 5d).

### API для клиентов

- Через API доступно всё, что умеет ядро для владельца: список ревью, ревью, файлы, отличия (в обоих режимах), комментарии и все действия. Веб-клиенту на шаге 6 и nvim позже считать ничего не нужно.
- Устройство API — в `core/README.md`.

### Временная страница

Настоящий интерфейс — на шагах 6–7. Пока по адресу открывается простая страница со списком ревью и их состоянием. Она обновляется сама и нужна, чтобы проверить этот шаг.

## Что не входит

- Команды агента, скилл и хуки, ревью своей сессии в `duet web` — шаг 5f.
- Настоящий интерфейс — шаги 6–7.
- Запуск ядра при входе в систему — в `docs/later.md`.
- Отдельное окно-приложение без вкладок и адресной строки — в `docs/later.md`.
- duet сам открывает вкладку, когда агент отдал ревью, — отклонено, в `docs/later.md`.

## Сценарии

Нумерация продолжает `docs/specs/core.md` (сценарии 1–91).

92. КОГДА ядро не запущено и вызвана любая команда duet, ТОГДА ядро запускается в фоне, команда выполняется, а терминал свободен.
93. КОГДА ядро уже работает и вызвана команда duet, ТОГДА второе ядро не запускается, команда работает с первым.
94. КОГДА вызван `duet web`, ТОГДА в браузере по умолчанию открывается новая вкладка (ревью, если оно указано, иначе список), а в терминале видна ссылка. Так же, даже если вкладка duet уже открыта.
95. КОГДА duet перезапустили или машину перезагрузили, ТОГДА прежние ссылки на ревью открывают те же ревью.
96. КОГДА в ядре что-то изменилось, ТОГДА все открытые вкладки показывают это сами, без перезагрузки.
97. КОГДА ядро остановлено, ТОГДА открытая вкладка показывает «duet не запущен». КОГДА ядро снова запущено, ТОГДА вкладка подключается сама и остаётся на том же месте.
98. КОГДА вызван `duet stop`, ТОГДА ядро останавливается, и после следующего запуска всё на месте.
99. КОГДА поставили новую версию duet, ТОГДА при следующей команде работающее старое ядро само заменяется новым.
100. КОГДА порт 4848 занят другой программой, ТОГДА duet работает на другом свободном порту и пишет ссылку с ним.
101. КОГДА к duet обращается другой компьютер в сети или чужой сайт в браузере, ТОГДА duet ничего не отдаёт и ничего не меняет.
102. КОГДА владелец открыл ревью в браузере, ТОГДА ревью сверяется с диском с видимым прогрессом, и дальше duet следит за его диском, пока работает.

Сценарий 47 заменяется таким: КОГДА агент отдал работу на ревью, ТОГДА он пишет в чат ссылку на ревью, а вкладку duet сам не открывает. Вкладку открывает `duet web`.
