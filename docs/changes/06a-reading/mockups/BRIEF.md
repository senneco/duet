# Задание для макетов веб-клиента duet

Макеты нужны, чтобы владелец выбрал направление вида до того, как пишется клиент. Каждый макет — **один самодостаточный HTML-файл** (весь CSS и JS внутри, без сети, без внешних шрифтов и библиотек; шрифты — системные стеки). Открывается двойным кликом из Finder. Интерфейс на русском.

Все макеты показывают **одни и те же данные и экраны** (ниже), чтобы их было удобно сравнивать. Отличаются — направлением вида.

## Что такое duet (коротко)

Локальный инструмент ревью работы ИИ-агента. Агент присылает файлы на ревью. Владелец читает отличия «база → текущая» (база — последнее, что он принял; до первого принятия — исходная версия «до задачи»), принимает файлы (`␣a` — пробел, потом a), комментирует выделенный текст. Главное — спокойно и быстро читать правки, точно знать, что принято, а что нет. Владелец работает в основном с клавиатуры (привычки vim), но всё доступно и мышью. Подробности: `docs/changes/06a-reading/proposal.md` (прочитай целиком).

## Общие правила вида (решены раньше, обязательны)

- Удалённый текст **не зачёркивать** (трудно читать) — красный фон. Добавленный — **синий** фон (не зелёный).
- Изменённые слова внутри строки подсвечены цельно, без «дыр»: пробелы и короткие слова между изменёнными словами входят в ту же подсветку.
- Две колонки: слева база, справа текущая; пустое место напротив удалённых/добавленных строк — **заштриховано**. Удалённые строки слева тоже на красном фоне.
- Одна колонка: удалённое и добавленное друг под другом (у прошлой версии были метки «КАК БЫЛО» / «НОВОЕ» — можно сохранить или придумать лучше).
- Markdown показан **документом** (отрисованный: заголовки, списки, таблица, блок кода) с подсветкой правок прямо в тексте. Код — исходником с номерами строк и **подсветкой синтаксиса**; неизменённые куски кода свёрнуты в строку «ещё N строк» (клик разворачивает).
- Значки дерева: не открывали — мигающий заполненный синий кружок; открывали, не принят — пустой синий кружок; принят — галочка; агент работает по комментариям — бегающие точки; непросмотренный ответ — рябь; удалён — серый; изменён на диске — пометка. Всё анимированное — анимировать по-настоящему (CSS).
- Важность блоков агента: ⇈ (главное) ↑ (важно) ↓ (можно пролистать).
- Тема: светлая и тёмная, переключатель в макете обязателен — оба варианта должны быть доведены.
- Без «стекла»/размытия под панелями (мигало в прошлой версии).
- Ничего не упоминать про конкретных агентов-моделей, кроме слов «Claude Code» / «Codex» как вида агента.

## Экраны (в одном файле, переключаются вкладками/ссылками вверху макета, отдельно от самого интерфейса — например, маленькая служебная панель в углу)

1. **Список ревью** (`http://duet.localhost:4848`). 4 ревью (данные ниже).
2. **Ревью: документ, одна колонка** — открыт `docs/specs/web.md`, документом, с правками.
3. **Ревью: документ, две колонки** — тот же файл, две колонки. Над базой пометка «до задачи · из git, HEAD».
4. **Ревью: код, две колонки** — открыт `server/web/tree.ts`, исходник, подсветка синтаксиса, свёрнутые куски.
5. **Ревью: код, одна колонка** — тот же файл.
6. **Меню `␣`** поверх экрана 2: действия с клавишами (`a` принять файл, `v` одна/две колонки, `m` документ/исходник; серым — то, что появится позже: `c` комментарий, `s` отправить, `r` ответ, `e` править).
7. **Записка агента** «начните отсюда» — открыта как страница.
8. **«Принять нельзя»** — сообщение после `␣a`: «Есть непросмотренный ответ агента» (с кнопкой «Открыть»).
9. **«duet не запущен»** — состояние вкладки, когда ядро остановлено (поверх экрана ревью).
10. **Список клавиш** (`?`).

Плюс на экране ревью всегда: заголовок ревью, «принято N из M», статус агента, переключатель темы и языка (RU/EN), подсказка про `␣`. Сверка с диском с прогрессом — покажи хотя бы в одном состоянии (например, тонкая полоса «сверяю с диском 12/40»).

### `server/web/tree.ts` — текущая

```ts
import { FileView, Block } from "./api";
import { icon } from "./icons";

// Дерево файлов ревью: папки по алфавиту, сворачиваются.
export function renderTree(files: FileView[], root: HTMLElement, open: string) {
  root.innerHTML = "";
  for (const node of buildTree(sortFiles(files))) {
    const row = document.createElement("div");
    row.className = node.folder ? "folder" : "row";
    row.textContent = node.name;
    row.prepend(icon(node.file));
    if (node.file?.path === open) {
      renderBlocks(node.file.blocks, row);
    }
    root.appendChild(row);
  }
}

export function pathLabel(path: string): string {
  return path.split("/").pop() ?? path;
}

export function sortFiles(files: FileView[]): FileView[] {
  return files.slice().sort((a, b) => a.path.localeCompare(b.path));
}

export function isAccepted(f: FileView): boolean {
  return f.state === "accepted";
}

export function countAccepted(files: FileView[]): number {
  return files.filter(isAccepted).length;
}

export function hasRipple(f: FileView): boolean {
  return f.ripple;
}

function renderBlocks(blocks: Block[], row: HTMLElement) {
  for (const b of blocks) {
    row.after(blockRow(b));
  }
}
```

(Здесь неизменённые функции `pathLabel`, `isAccepted`, `countAccepted`, `hasRipple` — кандидаты на сворачивание «ещё N строк».)
