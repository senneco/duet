# Шаг 7p4. Таймаут чтения репозитория

Чтение большой рабочей копии может занимать десятки секунд. Таймаут чтения ограничивает время одной проверки изменений и исходных версий файлов. Настройка общая для этой установки duet.

## Сценарии

- КОГДА пользователь запускает проверку без своей настройки, ТОГДА на чтение репозитория отводится 30 секунд.
- КОГДА пользователь выполняет `duet config read-timeout 60s`, ТОГДА duet сохраняет 60 секунд на этой машине и использует значение уже при следующей проверке. Команда принимает явную длительность с единицей времени от `1s` до `1h`. Без длительности команда показывает текущий лимит.
- КОГДА пользователь говорит «duet, установи таймаут чтения на минуту», ТОГДА агент через скилл duet выполняет ту же команду и сообщает сохранённое значение. Если длительность неоднозначна, агент уточняет её.
- КОГДА время чтения истекает, ТОГДА ошибка в терминале или в ревью показывает действующий лимит и готовую команду с увеличенным значением. Например, «Время чтения репозитория истекло (30 с). Чтобы увеличить лимит, выполните `duet config read-timeout 60s` и повторите проверку». При максимальном значении ошибка сообщает, что лимит достигнут.
- КОГДА чтение использует внешний плагин, ТОГДА он получает оставшееся время проверки. Совместимый плагин учитывает этот бюджет. Причина ошибки сохраняется, если плагин завершился раньше по другой причине.
- КОГДА команда получает недопустимую длительность, ТОГДА она сообщает причину и сохраняет прежнее значение.

Правила проверки полноты сохраняются. Для первого применения нужна версия duet с поддержкой настройки. Документация, тесты и примеры используют общий интерфейс и нейтральные имена плагинов.
