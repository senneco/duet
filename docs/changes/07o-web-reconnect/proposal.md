# Открытие ревью из нового чата

Статус: сделано; владелец подтвердил результат и поручил коммит и публикацию.

## Зачем

Владелец продолжил задачу в новом чате в том же каталоге, изменил файл существующего ревью и попросил `duet web`. Команда открыла главную страницу: привязка хранится по сессии, а новый чат ещё не подключён. Агент попросил ссылку вместо самостоятельного поиска.

Проверено по истории двух чатов и реализации команды: прежнее ревью существовало и содержало файлы текущей задачи. Правило восстановления в скилле требует заранее известной ссылки, поэтому этого недостаточно для нового чата.

## Что входит

- Просьба `duet web` в чате означает показать подготовленные материалы текущей задачи на ревью. Агент сам находит существующее ревью, восстанавливает подключение, передаёт пропущенные правки и открывает его.
- Поиск доступен через duet: агенту не требуется читать внутреннее хранилище или историю чужого чата.
- При выборе учитываются файлы текущей задачи. Одного совпадения каталога недостаточно, если там несколько подходящих ревью.
- Если ревью для задачи ещё нет, агент отправляет подготовленные материалы в новое ревью и открывает его.
- Базы, принятие файлов, комментарии и непросмотренный ответ сохраняются по действующим правилам. Подключение само по себе не означает, что правки уже переданы: агент проверяет результат.
- Из обычного терминала без сессии `duet web` по-прежнему открывает список.

## Что не входит

- Автоматическое подключение каждого нового чата без просьбы владельца.
- Выбор последнего ревью только по времени или каталогу.
- Перехват ревью у занятого агента и обход запретов записи.
- Изменение интерфейса браузера.

## Сценарии

1. КОГДА новый чат изменил файлы существующего ревью и владелец просит `duet web`, ТОГДА агент находит соответствующее ревью, подключается, передаёт правки и открывает его без просьбы прислать ссылку.
2. КОГДА в каталоге несколько ревью, но файлы текущей задачи однозначно определяют одно, ТОГДА агент использует его.
3. КОГДА после поиска остаётся несколько равнозначных вариантов, ТОГДА агент задаёт один вопрос с найденными названиями и ссылками.
4. КОГДА для подготовленных материалов задачи ещё нет ревью, ТОГДА агент создаёт его и открывает.
5. КОГДА другой агент занят в нужном ревью, ТОГДА подключение не происходит; владелец получает понятное объяснение действующего ограничения.
6. КОГДА текущий чат уже подключён, ТОГДА открывается его ревью; агент проверяет, что все подготовленные материалы переданы.
7. КОГДА `duet web` вызван вне сессии агента, ТОГДА открывается список ревью.

## Проверка

Автоматические проверки поиска, неоднозначности, восстановления подключения и сохранения баз и комментариев. Изолированная проверка двух сессий: первая отправляет материалы, вторая меняет файл и открывает то же ревью. Проверка в браузере, что видны новые правки относительно прежней базы.

## Реализация и результат

- Владелец отдельно подтвердил: ограничения должны обеспечиваться программно.
- `duet reviews [файлы…]` — поиск без подключения и сверки диска.
- `duet web --files файлы…` — выбор единственного ревью по файлам, проверка полноты перечисленных материалов, подключение и передача правок перед открытием. Добавление файлов с исходными версиями остаётся за `duet submit`: duet сам исходные версии не добывает.
- Ядро повторно проверяет принадлежность файлов, подключает сессию и передаёт правки под одной блокировкой. Неоднозначность, занятый другой агент, правка владельца, прерывание, неотвеченные комментарии и ошибка чтения не превращаются в успешное открытие браузера.
- Скилл трактует `duet web` как поручение показать подготовленные материалы задачи и описывает поиск, восстановление и создание ревью без повторного разрешения.
- Проверено в Chrome на изолированных данных: второй чат открыл прежнее ревью, новый текст виден относительно прежней базы, файл требует принятия. Скриншот: `/tmp/duet-web-reconnect.png`. Регрессия: `server/browsertest/web-reconnect.mjs`.
- Автоматические проверки: `go test ./...`, `node --test server/webtest`.
- Проверенная сборка и обновлённый скилл установлены локально для обоих клиентов. Новые правила скилла доступны новым чатам; работающее ядро заменится новой сборкой при следующей команде duet.

Действующие требования перенесены в `docs/specs/agent-protocol.md` и `docs/specs/server.md`. Рабочие данные ревью при проверках не использовались. Владелец подтвердил результат и поручил коммит и публикацию.
