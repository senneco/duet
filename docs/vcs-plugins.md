# Подключение и разработка плагина репозитория

Встроенная поддержка git работает без настройки. Для другой системы сначала установите duet по [инструкции](../INSTALL.md), затем установите отдельную локальную программу по инструкции её автора. Без плагина duet не гарантирует распознавание произвольной сторонней системы: каталог может считаться находящимся вне репозитория.

## Подключение

```sh
duet plugin add my-vcs /absolute/path/to/plugin
duet plugin list
duet plugin check my-vcs /absolute/path/to/worktree
```

Имя: строчные латинские буквы, цифры и дефисы, начиная с буквы, до 64 символов. `git` зарезервировано. Имя должно совпадать с `workspace.provider` программы. Путь может содержать пробелы; заключите его в кавычки. Регистрация принимает путь, преобразует его в абсолютный и разрешает ссылки. Аргументов командной строки и shell-команды нет; при необходимости автор поставляет собственную исполняемую обёртку.

`add` проверяет версию и операции. `check` делает полный согласованный сбор, выводит JSON-снимок и проверяет выбор провайдера. Код выхода 0 означает успешную проверку поддерживаемого репозитория; 1 — ошибку, неполноту либо отсутствие распознанного репозитория. Неподдерживаемый файл тоже делает проверку неполной. Успешный `hello` сам по себе не подтверждает работу с репозиторием.

Регистрация находится в `$DUET_HOME/plugins/NAME.json`, по умолчанию `~/.duet/plugins/`. Изменения применяются при следующем сборе без перезапуска. Повторный `add` не заменяет существующую запись. Для смены пути:

```sh
duet plugin remove my-vcs
duet plugin add my-vcs /new/absolute/path/to/plugin
```

Обновление программы по прежнему пути не требует перерегистрации. После обновления выполните `check`. Удаление регистрации отключает распознавание этой системы, поэтому удалять нужный плагин для обхода ошибки полноты нельзя. После восстановления программы используйте «Проверить снова» в ревью.

Duet опрашивает все явно зарегистрированные внешние плагины. Один распознавший каталог плагин выбирается; несколько — явная неоднозначность. Если все ответили, что репозитория нет, используется встроенный git. Любая ошибка регистрации или процесса блокирует сбор: она не скрывается переходом к git. Внешний провайдер может обслуживать git, что позволяет проверять совместимость на известной реализации.

Плагин — доверенная локальная программа с правами пользователя. Duet не изолирует её и не может доказать полноту сообщённого ею списка. Плагин обязан выполнять только чтение, не создавать коммиты и не менять индекс или рабочие файлы. Само наличие программы или конфигурации в проверяемом репозитории ничего не запускает. Все команды установки должны исходить из явного решения пользователя.

## Протокол 1

Каждая операция — отдельный запуск исполняемого файла без аргументов. Рабочий каталог процесса — каталог исполняемого файла. Окружение наследуется от duet; относительные пути репозитория нельзя вычислять от рабочего каталога процесса. Запрос — один JSON-объект UTF-8 в stdin, затем EOF. Ответ — один JSON-объект UTF-8 в stdout, затем завершение с кодом 0. Логи в stdout запрещены. Stderr можно использовать для диагностики при ручном запуске; duet не включает его в сообщение ошибки процесса.

В каждом запросе и ответе обязательно `protocol: 1`. Ответ содержит ровно один из `result` и непустого `error`. Пример ошибки:

```json
{"protocol":1,"error":"cannot read repository state"}
```

Ненулевой код выхода, некорректный JSON, неизвестные поля, отсутствующие обязательные данные и другая версия протокола считаются ошибкой. На чтение репозитория целиком отводится 30 секунд по умолчанию. Текущий лимит показывает `duet config read-timeout`. Команда `duet config read-timeout 60s` меняет таймаут для этой установки со следующей проверки. Допустимы длительности от `1s` до `1h`. Рукопожатие `hello` ограничено пятью секундами. Stdout ограничен 32 МиБ, stderr — 64 КиБ. Процесс обязан завершиться и закрыть потоки; фоновых процессов быть не должно. Эти ограничения тоже могут стать причиной неполноты большой рабочей копии.

Duet передаёт оставшийся бюджет операции в `DUET_PLUGIN_TIMEOUT_MS` в
целых миллисекундах. Плагин может использовать его, чтобы остановить дочерние
процессы до окончания времени и вернуть `{"protocol":1,"error":"operation timed out","error_code":"timeout"}`.
Duet покажет действующий лимит и команду для его увеличения. При запуске старой
версией duet переменная отсутствует. В этом случае плагин использует прежний
формат ответа без `error_code`.

### hello

Запрос:

```json
{"protocol":1,"operation":"hello"}
```

Ответ:

```json
{"protocol":1,"result":{"operations":["detect","state","original"]}}
```

### detect

```json
{"protocol":1,"operation":"detect","directory":"/work/project/subdir"}
```

При достоверном отсутствии репозитория — `{"protocol":1,"result":null}`. При ошибке определения — `error`, не `null`. Распознанная рабочая копия:

```json
{"protocol":1,"result":{"provider":"my-vcs","root":"/work/project","id":"stable-worktree-id"}}
```

`root` — абсолютный канонический путь существующего корня без символических ссылок, содержащий `directory`. `id` — непустая стабильная идентичность отдельной рабочей копии. Две рабочие копии с общей историей имеют разные id. `provider` совпадает с именем регистрации.

### state

```json
{"protocol":1,"operation":"state","workspace":{"provider":"my-vcs","root":"/work/project","id":"stable-worktree-id"}}
```

```json
{"protocol":1,"result":{"revision":"immutable-commit-id","token":"state-fingerprint","changes":[{"path":"src/file.txt","status":"modified"},{"path":"new-name.txt","status":"renamed","previousPath":"old-name.txt"}],"diagnostics":[]}}
```

`revision`, `token` и `changes` обязательны. Пустая revision допустима только до первого коммита. Нет изменений — `changes: []`, не `null`. Порядок списка и диагностик должен быть стабильным между чтениями одного состояния. `token` непустой и меняется при смене коммита, набора изменений и содержимого индекса, в том числе когда диск совпал с коммитом.

В список входят **все** незакоммиченные изменения всего корня, включая подготовленные, удаления, переименования и новые неигнорируемые файлы. Duet сам читает текущее содержимое с диска. `status` — непустое описание изменения; duet не использует его для исключения путей. `previousPath` связывает прежний путь при переименовании; duet добавит и его. Пути — уникальные относительные UTF-8 с `/`, без `..`, нулевого символа и выхода из корня.

Проблема, при которой доступна часть списка, записывается в `diagnostics`:

```json
{"path":"asset.bin","code":"unsupported","message":"binary object"}
```

Пустой или пропущенный `path` означает общую проблему. `code` и `message` непустые. Частичный список без диагностики недопустим. Если список получить нельзя — ответ `error`. Вложенный самостоятельный репозиторий, конфликт и скрывающие изменения настройки требуют явной диагностики.

### original

```json
{"protocol":1,"operation":"original","workspace":{"provider":"my-vcs","root":"/work/project","id":"stable-worktree-id"},"revision":"immutable-commit-id","path":"src/file.txt"}
```

Читается **указанный неизменяемый коммит**, даже если текущий коммит уже изменился. Пустая revision передаётся без поля `revision` и означает отсутствие первого коммита. Формы `result`:

```json
{"kind":"text","text":"original text\n","mode":"100644"}
```

```json
{"kind":"text","text":"","mode":"100644"}
```

```json
{"kind":"absent"}
```

```json
{"kind":"unsupported","reason":"symbolic link","mode":"120000"}
```

Для текста `mode` — `100644` или `100755`; пустой `text` можно опустить. Бинарные данные и не-UTF-8 нельзя возвращать как текст. Отсутствие файла — `absent`; ошибка чтения — `error`. Нельзя превращать ошибку в пустой файл или отсутствие. Для `unsupported` обязательна причина; `mode` необязателен.

## Пример и проверка автора

[Пример на Go](../vcs/example/main.go) оборачивает встроенный git в отдельный процесс. Это работающий образец транспорта и эквивалентности, а не реализация новой системы. В клоне duet:

```sh
go build -o /tmp/duet-example-git ./vcs/example
DUET_HOME=/tmp/duet-plugin-demo duet plugin add example-git /tmp/duet-example-git
DUET_HOME=/tmp/duet-plugin-demo duet plugin check example-git /absolute/path/to/git/worktree
DUET_HOME=/tmp/duet-plugin-demo duet plugin remove example-git
```

Нужна сборка duet с поддержкой `plugin`. В примере имя фиксировано: `example-git`. Пример можно скопировать в отдельный проект; реализацию `Provider` заменяют адаптером нужной системы. Исходники транспорта и структур: [plugin.go](../vcs/plugin.go), [vcs.go](../vcs/vcs.go).

Автор плагина проверяет: соседние каталоги, разные рабочие копии, подготовленную версию при другом содержимом диска, новые и игнорируемые файлы, удаление и переименование, пустой файл и отсутствие, отсутствие первого коммита, смену коммита во время сбора, неподдерживаемые объекты, ошибки чтения и недоступную программу. Два чтения исходников и диска окружены тремя чтениями состояния и повторным определением рабочей копии. При расхождении duet повторяет сбор не более трёх раз, затем сохраняет неполноту.

`go test ./vcs ./core ./app` проверяет настоящий внешний процесс, транспортные ошибки, регистрацию, равенство снимков git и правила принятой базы. Проверка совместимости подтверждает форму и наблюдаемую стабильность; полноту и режим только чтения автор проверяет на тестовых репозиториях своей системы.
